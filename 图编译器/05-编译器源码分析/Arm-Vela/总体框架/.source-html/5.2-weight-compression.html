Weight compression is a critical optimization technique used in the Ethos-U Vela compiler to reduce the memory footprint of neural network weights. This page explains how weights and biases are compressed, encoded, and prepared for efficient execution on Arm Ethos-U Neural Processing Units (NPUs).

For information about the overall command stream generation process, see Command Stream Generation.

Overview

Weight compression in the Ethos-U Vela compiler serves multiple purposes:

  1. Memory Efficiency: Reduces the storage requirements for weights and biases
  2. Transfer Efficiency: Minimizes the bandwidth needed to transfer weights to the NPU
  3. Execution Optimization: Arranges weights in a format that aligns with how the NPU processes them

The compression process transforms weights from their standard representation (typically OHWI format) into an encoded format that is optimized for the specific Ethos-U hardware architecture in use.

Compression Process

The weight compression process involves several key components:

Sources: ethosu/vela/weight_compressor.py67-91

Key Components:

  1. WeightCompressionConfig: Contains metadata that uniquely identifies a weight compression configuration. If two tensors have identical weight compression configs, they will have identical compressed weights.

  2. ScaleCompressionConfig: Contains information about scale compression configuration, including scale value ID and input/output feature map scales.

  3. NpuWeightTensor: A specialized tensor class that holds compressed weights and related information such as buffer sizes and encoded ranges.

  4. WeightRange: Tracks offsets and sizes of compressed weight and scale data within the encoded buffer.

  5. CompressedWeightCache: A global cache that stores previously compressed weights to avoid redundant compression operations.

Weight Encoding

The weight encoding process transforms neural network weights into a compressed format optimized for the Ethos-U NPU architecture:

The core encoding functionality is provided by the encode_weights function, which:

  1. Takes weights in OHWI layout along with configuration parameters
  2. Applies architecture-specific processing based on the Ethos-U accelerator type
  3. Handles different block traversal strategies (DEPTH_FIRST or PART_KERNEL_FIRST)
  4. Supports different dilation factors
  5. Returns encoded weights as a bytearray

For depthwise convolutions, a special encoding approach is used that's optimized for the unique characteristics of depthwise operations.

Sources: ethosu/vela/weight_compressor.py141-199

Bias and Scale Encoding

Alongside weight compression, bias and scale encoding is essential for preserving the quantized neural network's accuracy:

The encode_bias function:

  • Takes a 64-bit signed bias value (of which 40 bits are used)
  • Takes a 32-bit scale value and 6-bit shift value
  • Packs them into an 80-bit (10-byte) structure
  • The resulting byte array is optimized for the NPU's bias handling requirements

Sources: ethosu/vela/weight_compressor.py202-231

Architecture-Specific Considerations

Weight compression adapts to the specific Ethos-U architecture in use:

  • Ethos-U55/U65: Different configurations (32, 64, 128, 256, 512) affect:

    • Input feature map (IFM) and output feature map (OFM) micro-block sizes
    • SHRAM bank configurations
    • Number of cores available for processing

  • Block Traversal Strategies:

    • DEPTH_FIRST: Processes the entire depth dimension before moving to the next spatial location
    • PART_KERNEL_FIRST: Processes part of the kernel at each spatial location before moving to the next part

  • Data Formats:

    • Supports different bit depths (8, 16, 32-bit)
    • Handles different quantization parameters

The system automatically selects the optimal traversal strategy for each operation type based on the kernel dimensions, feature map depths, and target architecture.

Caching Mechanism

The weight compression system implements a caching mechanism to avoid redundant encoding operations:

Key aspects of the caching mechanism:

  1. Cache Key: Uses the WeightCompressionConfig as a unique identifier for each weight tensor
  2. Lookup: Checks if weights with identical configurations have already been compressed
  3. Storage: Stores compressed weights to avoid redundant compression
  4. Benefits: Significantly reduces compilation time when the same weights are used multiple times with the same configuration

Integration with Command Stream Generation

Compressed weights are integrated into the NPU command stream generation process:

The compressed weights and biases are incorporated into the command stream through:

  1. generate_weights(): Takes compressed weights and generates the appropriate register commands
  2. generate_biases(): Takes encoded bias/scale values and generates register commands
  3. These commands are then integrated into the full NPU command stream

The command stream generator checks alignment and length requirements, ensuring the compressed data meets hardware constraints:

  • Weight addresses must be 16-byte aligned
  • Weight lengths must be multiples of 16 bytes
  • Scale and bias addresses must meet alignment requirements

Sources: ethosu/vela/register_command_stream_generator.py443-560

Main Compression Function

The main compression function that ties everything together is encode_weight_and_scale_tensor, which:

  1. Creates appropriate compression configurations
  2. Checks the cache for previously compressed weights
  3. Processes scales and biases from the tensor
  4. Performs zero-point correction on weights
  5. Slices weights into appropriate blocks for processing
  6. Encodes weights using architecture-specific parameters
  7. Handles double-buffering requirements
  8. Returns a compressed weight tensor ready for use in command stream generation

This function efficiently manages the overall compression workflow, ensuring weights are properly prepared for the Ethos-U NPU execution.
