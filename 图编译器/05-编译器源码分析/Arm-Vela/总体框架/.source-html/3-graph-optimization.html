Graph optimization is a critical early phase in the Arm Ethos-U Vela compiler pipeline that transforms neural network graphs to make them more efficient for execution on Neural Processing Units (NPUs). The optimization process analyzes the network structure, modifies operations, fuses layers where possible, and converts unsupported patterns to equivalent supported forms. These transformations aim to maximize NPU utilization while ensuring computational accuracy.

For information about operation scheduling that follows graph optimization, see Operation Scheduling, and for command stream generation, see Command Stream Generation.

Optimization Pipeline Overview

The graph optimization pipeline takes a neural network graph (either TensorFlow Lite or TOSA format) as input and applies a series of transformations to improve execution efficiency on the Ethos-U NPU hardware.

Sources: ethosu/vela/graph_optimiser.py28-47 ethosu/vela/tflite_graph_optimiser.py81-796

The main entry point for graph optimization is the optimise_graph function, which performs the following steps:

  1. Routes the optimization to either TFLite or TOSA-specific optimizers based on the network type
  2. Applies format-specific graph transformations
  3. Performs post-optimization checks to ensure all operations are correctly handled
  4. Returns the optimized graph for further processing

Format-Specific Optimization

Vela supports both TensorFlow Lite and TOSA graph formats, with dedicated optimization modules for each.

TFLite Graph Optimization

The TFLite graph optimizer applies a sequence of rewrites to transform the graph for better NPU execution.

Diagram: TFLite Graph Optimization Flow

Sources: ethosu/vela/tflite_graph_optimiser.py84-413

Key TFLite optimization techniques include:

  1. Removing passthrough tensors: Eliminates unnecessary tensor operations like Identity
  2. Rewriting pattern-specific operations:
    • Concat operations are rewritten to use AvgPool for each input
    • Split operations are converted to SplitSliceRead operations
    • ResizeBilinear/ResizeNearestNeighbor operations are converted to depthwise convolutions or average pooling
  3. Converting complex operations to simpler ones:
    • ArgMax is rewritten as a sequence of depthwise convolution and maxpool operations
    • LeakyRelu is rewritten using elementwise operations
  4. Input/Output shape and padding adjustments

TOSA Graph Optimization

For TOSA graphs, similar optimizations are applied but with adjustments for the different input format.

Key Optimization Classes and Functions

Core Optimization Components

The graph optimization system consists of several key components:

  1. Graph Optimiser (graph_optimiser.py): The main entry point that coordinates optimization
  2. TFLite Graph Optimiser (tflite_graph_optimiser.py): Handles TFLite-specific optimizations
  3. TOSA Graph Optimiser (tosa_graph_optimiser.py): Handles TOSA-specific optimizations
  4. Supported Operators (tflite_supported_operators.py): Defines operation support constraints
  5. Operation and Tensor classes: Core data structures manipulated during optimization

Constraint Checking

After optimization, operations undergo constraint checking to determine if they can run on the NPU. These constraints include:

  1. Generic constraints that apply to most operations:

    • Input/output tensor data types must be supported (uint8, int8, int16, int32)
    • Tensor dimensions must be in valid ranges
    • Proper quantization parameters must be present
    • Batch size restrictions

  2. Operation-specific constraints:

    • Convolution: kernel size, stride, dilation limits
    • Pooling: filter size and stride limits
    • Elementwise: broadcasting limitations
    • Activation: supported function types

Post-Optimization: Pass Packing

After graph optimization, operations are packed into "passes" for execution:

Diagram: Pass Packing Flow

Sources: ethosu/vela/pass_packing.py95-196

Pass packing categorizes operations into several types:

  • Main operations: Convolutions, pooling operations that run on the MAC unit
  • ElementWise operations: Operations that run on the elementwise unit
  • Post operations: Activations and other post-processing operations
  • Memory-only operations: Shape transformations that don't perform computation
  • CPU operations: Operations that must run on the CPU

Architecture Compatibility

The graph optimization process is sensitive to the target Ethos-U architecture (U55, U65, or U85), as different architectures have different capabilities and constraints. The optimization passes ensure the resulting graph leverages the specific features of the target architecture.

Sources: ethosu/vela/graph_optimiser.py28-30

Conclusion

Graph optimization is a fundamental step in the Vela compiler that transforms neural networks to run efficiently on Ethos-U NPUs. Through a series of sophisticated transformations, it ensures operations are compatible with hardware constraints while maximizing performance. The optimized graph then proceeds to the scheduling phase, where operations are organized for actual execution on the NPU.

After graph optimization is complete, the next step in the pipeline is Operation Scheduling, where optimized operations are scheduled for execution.
