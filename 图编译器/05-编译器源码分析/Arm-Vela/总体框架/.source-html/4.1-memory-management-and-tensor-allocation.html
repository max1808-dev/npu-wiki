This page documents how the Ethos-U Vela compiler manages memory and allocates tensors during the neural network compilation process. It explains the live range analysis, tensor allocation strategies, and memory optimization techniques used to efficiently map tensors to memory addresses.

For information about operation scheduling, which works closely with memory management, see Operation Scheduling.

Overview

The Ethos-U NPU has limited on-chip memory, making efficient memory management crucial for performance. Vela's memory management system analyzes when tensors are created and consumed, determines overlapping lifetimes, and assigns memory addresses to minimize overall memory usage.

Live Range Analysis

Live range analysis tracks when tensors are "alive" during network execution to identify opportunities for memory reuse. A tensor is alive from when it's created until its last use.

Core Components

  • LiveRange: Represents a tensor's lifetime between creation and last use
  • LiveRangeGraph: Manages the collection of live ranges and calculates memory usage over time

Sources: ethosu/vela/live_range.py33-111 ethosu/vela/live_range.py116-158

Live Range Extraction

Live ranges are extracted from the network schedule by tracking when tensors are created and consumed:

The system extracts live ranges based on the scheduled execution of operations:

  1. Assigns a time index to each operation
  2. For each tensor, identifies when it's created (start_time) and last consumed (end_time)
  3. Builds a LiveRangeGraph containing all tensor live ranges
  4. Analyzes which tensors' lifetimes overlap and which don't

Memory Reuse Opportunities

Two key memory optimization techniques are identified during live range analysis:

  1. Elementwise Operation Fusion: For elementwise operations, the output can often reuse the input tensor's memory
  2. Cascade Buffer Sharing: Operations in a cascade can use smaller "rolling buffers" instead of full-sized buffers

Tensor Allocation Strategies

Vela implements three allocation strategies with different tradeoffs between allocation speed and memory efficiency.

1. Linear Allocation

The simplest approach, allocating tensors sequentially in memory:

2. Greedy Allocation

Sorts live ranges by start time and allocates each tensor to the lowest possible address without overlapping existing allocations:

Sources: ethosu/vela/greedy_allocation.py1-78

3. Hill Climb Allocation

Most sophisticated strategy that iteratively improves a starting allocation:

  1. Starts with a heuristic allocation
  2. Identifies "bottlenecks" (tensors with highest memory address)
  3. Swaps allocation order of tensors affecting the bottleneck
  4. If memory usage improves, keeps the change; otherwise reverts
  5. Repeats until optimal solution found or iteration limit reached

This strategy is particularly effective for complex networks but takes longer to compute.

Cascade Building for Memory Optimization

Cascades are sequences of operations whose intermediate buffers can be shared to reduce memory usage.

What is a Cascade?

A cascade is a sequence of operations where:

  • The output of one operation is only consumed by the next operation
  • The operations can be executed serially
  • The full intermediate tensor doesn't need to be stored

Instead of allocating full-sized buffers for each intermediate tensor, cascades use smaller "rolling buffers" that hold only the portion of data needed for the next operation.

Cascade Building Process

The CascadeBuilder identifies candidates for cascading and builds optimal cascades:

When building cascades, the system considers:

  1. Whether operation types support cascading
  2. If operations form a linear chain
  3. Memory savings compared to non-cascaded execution
  4. If the operations have compatible input/output shapes

Conclusion

Efficient memory management is crucial for optimal execution of neural networks on Ethos-U NPUs. Vela's memory management system:

  1. Uses live range analysis to track tensor lifetimes
  2. Identifies opportunities for memory reuse
  3. Builds cascades to share intermediate buffers
  4. Applies different allocation strategies to optimize memory usage
  5. Supports different memory types and areas

This system allows Vela to fit larger networks within limited NPU memory and optimize performance by reducing memory transfers.
