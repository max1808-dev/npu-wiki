Operation scheduling is a critical component of the Ethos-U Vela compiler that determines how neural network operations are executed on the Ethos-U NPU. The scheduler creates and searches for an optimal plan for the network, selecting block configurations and subdivisions for operations to balance memory usage and performance. This page explains the scheduling process, cascading mechanism, and optimization strategies used in the Vela compiler. For information about memory management and tensor allocation as part of the scheduling process, see Memory Management and Tensor Allocation.

Scheduler Overview

Sources: ethosu/vela/scheduler.py429-434 ethosu/vela/scheduler.py413-427

The Scheduler is responsible for finding an optimal execution strategy for neural network operations on the Ethos-U NPU. It works with a graph representation where operations are nodes (SchedulerOperation) and tensors are edges (Connection) between operations.

Key Components

  • Scheduler: Main class that orchestrates the scheduling process
  • Schedule: Contains a solution of how to schedule an NPU subgraph and its cost
  • SchedulerOperation: Represents an operation to be scheduled
  • SchedulerOpInfo: Contains metadata about a scheduled operation
  • Connection: Represents tensor connections between operations

The scheduler determines how to execute operations optimally by considering memory constraints, operation dependencies, and NPU hardware capabilities. It creates different schedules with varying trade-offs between memory usage and performance, ultimately selecting the most appropriate one based on the optimization strategy.

Scheduling Process

Sources: ethosu/vela/scheduler.py432-564 ethosu/regor/compiler/scheduler.cpp80-151

The scheduling process consists of the following main steps:

  1. Create Scheduler Representation: Converts the neural network graph into scheduler-specific data structures
  2. Create Initial Schedule: Generates a maximum schedule where operations use full tensors
  3. Propose Minimal Schedule: Attempts to minimize memory usage by striping operations
  4. Build Cascades: Groups operations into cascades to optimize memory usage
  5. Optimize Schedule: Balances memory usage and performance
  6. Propose Buffering: Adds weight buffering to further optimize performance
  7. Memory Allocation: Allocates memory for tensors based on the final schedule

Each step contributes to finding an optimal execution strategy that meets memory constraints while maximizing performance.

Initial Schedule Creation

The scheduler begins by creating an initial "maximum" schedule where each operation uses full tensors without any optimization:

For each operation, the scheduler:

  1. Uses the full output feature map shape
  2. Finds an optimal block configuration for the NPU hardware
  3. Encodes weights and scales if applicable
  4. Estimates performance using the NPU performance model

This initial schedule provides a baseline for further optimization and represents the maximum memory usage scenario.

Operation Cascading

One of the most important optimizations in the scheduler is operation cascading, which groups consecutive operations to minimize memory usage:

Sources: ethosu/vela/cascade_builder.py86-350

A cascade connects operations such that the output of one operation becomes the input of the next. Instead of storing full tensors, cascaded operations use smaller rolling buffers that significantly reduce memory usage.

Cascading Criteria

Operations can be cascaded if they meet these criteria:

  • They are not of type VectorProduct or ReduceSum
  • The output stripe is smaller than the full output shape
  • They have no read offsets
  • For elementwise operations, the IFM must be non-constant/non-scalar/non-broadcast
  • They are in the correct order and have compatible shapes

The cascade builder starts with a minimal schedule and attempts to build cascades to optimize memory usage while ensuring operations run efficiently.

Sources: ethosu/vela/cascade_builder.py95-106 ethosu/vela/cascade_builder.py153-308

Memory Management in Scheduling

The scheduler uses live range analysis to track tensor lifetimes and optimize memory allocation:

The scheduler maintains a memory snapshot that tracks memory usage throughout the execution timeline. This helps in estimating peak memory usage and finding opportunities for memory optimization.

Key aspects of memory management:

  • Tracking tensor lifetimes (start and end times)
  • Identifying opportunities for tensor reuse
  • Estimating memory requirements for different schedule options
  • Ensuring memory usage stays within constraints

Weight Buffering

Another important optimization is weight buffering, which improves performance by staging weights in faster memory:

Sources: ethosu/vela/scheduler.py649-924

The weight buffering process:

  1. Analyzes operations with weights to determine if buffering would improve performance
  2. Encodes weights and calculates buffer sizes and DMA transfer times
  3. Decides on the buffering strategy (no buffer, single buffer, or double buffer)
  4. For double buffering, overlaps weight transfer with computation to hide latency

The scheduler considers the slack cycles available from previous operations and the available memory when making buffering decisions.

Sources: ethosu/vela/scheduler.py702-771

Performance Estimation

The scheduler uses a performance model to estimate execution cycles and memory bandwidth for different schedule options:

Sources: ethosu/vela/npu_performance.py104-171 ethosu/vela/npu_performance.py447-777

The performance estimation involves:

  1. Building a performance query with operation details (shapes, formats, memory areas)
  2. Estimating operation execution cycles based on the operation type and block configuration
  3. Estimating element access counts for inputs, outputs, and weights
  4. Calculating DMA transfer cycles for weights, LUTs, and other data
  5. Estimating memory bandwidth requirements for different memory areas

This performance model is used both during scheduling to evaluate different proposals and for providing a final performance estimate of the compiled network.

Optimization Strategies

The scheduler supports two primary optimization strategies:

  1. Size Optimization: Minimizes memory usage, potentially at the cost of performance
  2. Performance Optimization: Prioritizes execution speed, while keeping memory usage within limits

Sources: ethosu/vela/scheduler.py83-90 ethosu/regor/compiler/scheduler.cpp95-121

The chosen strategy affects how the scheduler:

  • Builds cascades
  • Decides on weight buffering
  • Selects between alternative schedules
  • Allocates memory for tensors

The scheduler always attempts to meet the memory constraints specified in the configuration while optimizing for the selected goal.

Summary

The operation scheduler is a fundamental component of the Ethos-U Vela compiler that:

  1. Represents and schedules neural network operations for execution on the NPU
  2. Optimizes memory usage through cascading and tensor reuse
  3. Improves performance through weight buffering and operation ordering
  4. Estimates performance and memory usage of different schedule options
  5. Balances memory and performance trade-offs based on the chosen optimization strategy

The scheduler's output determines how operations are executed on the NPU, affecting both memory usage and execution performance of the compiled neural network.
