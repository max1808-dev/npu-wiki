Purpose and Scope

This document explains the cascade building process in the Ethos-U Vela compiler, which is a critical memory optimization technique used during scheduling. Cascading enables multiple sequential operations to share memory through rolling buffers, significantly reducing peak memory usage while maintaining performance. This page covers how cascades are identified, built, and optimized within the scheduler's execution plan.

For related topics, see Operation Scheduling for the overall scheduling process and Memory Management and Tensor Allocation for general memory allocation strategies.

What is a Cascade?

A cascade is a sequence of operations where the output of one operation is the input to the next, and where these operations can be executed with a shared "rolling buffer" instead of allocating full-sized intermediate feature maps. The goal is to minimize memory usage while preserving execution efficiency.

In a non-cascaded execution, each operation requires full input and output feature maps to be allocated in memory. With cascading, operations can work with partial feature maps, processing data stripe by stripe, and reducing peak memory requirements.

Cascading Criteria

Not all operations can be cascaded. The Vela compiler evaluates several criteria to determine if operations are suitable for cascading:

Key criteria for cascadable operations include:

  • Not being a Vector Product, ReduceSum, or Default block type
  • Processing data in stripes (stripe height less than full output height)
  • Having no read offsets
  • Passing elementwise cascading rules (for elementwise operations)
  • Not being certain special operations like Conv2DBackpropInput
  • Not using TILE padding

Elementwise Operation Cascading Rules

Elementwise operations have special cascading rules:

For binary elementwise operations:

  • Primary input (IFM) must be a regular feature map (not constant, scalar, or broadcast)
  • Secondary input (IFM2) must be a constant or scalar

Rolling Buffers

The core memory-saving mechanism in cascades is the rolling buffer, which enables partial processing of feature maps.

Rolling Buffer Shape Calculation

Rather than allocating the full feature map size, a rolling buffer only needs to be large enough to:

  1. Store the output from the current stripe of the producer operation
  2. Provide sufficient input for the consumer operation's next stripe
  3. Align with hardware requirements (e.g., depth rounded to 16)

Cascade Building Process

The cascade building process occurs during scheduling and follows these key steps:

The algorithm prioritizes memory usage reduction, seeking to minimize the peak memory required for execution. It builds cascades incrementally, evaluating memory usage at each step and finalizing the cascade when adding more operations no longer improves memory usage.

Sources: ethosu/vela/scheduler.py1001-1032 ethosu/vela/cascade_builder.py164-350

Memory Usage Estimation

For each potential cascade, the CascadeBuilder estimates the memory required with and without cascading:

For Non-Cascaded Operations:

  • Full IFM size
  • Full OFM size
  • Weight buffers
  • Any non-local memory usage

For Cascaded Operations:

  • Initial IFM size (for first operation in cascade)
  • Combined rolling buffer sizes
  • Final OFM size (for last operation in cascade)
  • Weight buffers
  • Any non-local memory usage

The algorithm builds cascades that minimize total memory usage.

Cascade Building in the Scheduler

The scheduler integrates cascade building in its optimization process:

The process starts with a minimal schedule, then builds cascades to optimize memory usage. After cascades are built, the scheduler can further optimize each sub-schedule, and finally calculates live ranges accounting for the rolling buffers in cascades.

The BufferMap class maintains a mapping of producer-consumer pairs to their buffer requirements:

When determining buffer sizes between operations, the system either:

  1. Uses full feature map sizes when required (for subgraph inputs/outputs or operations requiring full feature maps)
  2. Uses rolling buffer sizes for operations that can be cascaded

Performance Considerations


While cascades primarily optimize memory usage, they can also affect performance:


    

  1. Cascading reduces memory transfers between operations
    2. 

  2. The performance estimation system (npu_performance.py) accounts for cascades when estimating cycle costs
