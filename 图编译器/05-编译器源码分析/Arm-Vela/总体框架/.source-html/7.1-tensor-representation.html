This page documents how neural network tensors are represented internally within the Ethos-U Vela compiler. Understanding tensor representation is critical for working with the compiler, as tensors are the fundamental data structures used to represent inputs, outputs, weights, and intermediate activations in neural networks.

For information about how tensors are serialized to the TensorFlow Lite format, see TFLite Serialization.

Core Tensor Representation

In Vela, tensors are represented by the Tensor class, which holds all information about a tensor's data, shape, memory requirements, and other properties.

Tensor Memory Representation

Tensors can have different memory representations for different purposes:

  1. Logical Shape: The actual tensor dimensions as seen by the neural network operations
  2. Storage Shape: The shape in memory, which may include padding to meet alignment requirements
  3. Bandwidth Shape: Used for bandwidth calculations, may be different from storage shape

The memory representation of a tensor depends on:

  • Tensor format (NHWC, NHCWB16, etc.)
  • Storage rounding quantum (architecture-specific)
  • Brick size (format-specific layout parameter)
  • Alignment requirements

Tensor Storage Size and Memory Allocation

The storage size of a tensor is calculated based on:

def storage_size(self, scale: float = 1.0) -> int:
    raw_size = self.storage_elements() * self.element_size() * scale
    if raw_size == 0:
        raw_size = 1  # force it to take up space
    rounded_size = numeric_util.round_up(numeric_util.round_up_to_int(raw_size), self.alignment)
    return rounded_size

Key factors:

  • Number of elements in the storage shape
  • Element size in bytes
  • Compression scale (if applicable)
  • Alignment requirements

The actual memory allocation is handled by:

  1. Calculating tensor storage sizes
  2. Assigning addresses in memory based on the tensor allocation strategy
  3. Storing addresses in the TensorAddressMap (class that keeps track of tensor addresses)

Tensor Memory Addressing

Tensors use a coordinate system to access elements in memory. The address_for_coordinate method calculates memory addresses based on:

  • Logical coordinates in the tensor (N, H, W, C)
  • Storage shape and format
  • Strides in memory
  • Base address assigned during memory allocation

The calculation differs based on the tensor format:

  • NHWC: Standard layout with channels as the innermost dimension
  • NHCWB16: Block-based layout with channel blocks of size 16
  • WeightsCompressed: Special format for compressed weights

Tensor Quantization

Tensors often use quantized representations to reduce memory and computation requirements. Quantization parameters are stored in the QuantizationParameters class:

The quantization process maps real values to integers using:

  • Scale factor (scale_f32)
  • Zero point (zero_point)
  • Quantized range (quant_min, quant_max)

For per-axis quantization, scale_f32 and zero_point are arrays rather than scalar values.

The dequantize method performs the reverse mapping to recover the approximate real values:

def dequantize(self, values) -> np.ndarray:
    return np.subtract(values, self.zero_point) * self.scale_f32

Special Tensor Types

Constant Tensors

Created using create_const_tensor to represent constant values:

def create_const_tensor(name, shape, dtype, values, purpose=TensorPurpose.Unknown, quantization=None):
    const_tensor = Tensor(shape, dtype, name + "_0")
    const_tensor.purpose = purpose
    const_tensor.quantization = quantization
    const_tensor.values = np.array(values).astype(dtype.as_numpy_type())
    
    # Create a Const operation 
    const_op = Operation(Op.Const, name)
    const_op.set_output_tensor(const_tensor)
    const_op.set_ifm_ofm_shapes()
    return const_tensor

Conclusion

The tensor representation in Vela provides a flexible system for handling various types of neural network data with different memory layouts, storage requirements, and quantization parameters. The design supports the specific needs of Ethos-U NPUs while providing efficient memory management and addressing schemes.

Understanding how tensors are represented, stored, and accessed is crucial for:

  • Modifying the compiler to support new operations
  • Optimizing memory usage for neural networks
  • Debugging memory-related issues
  • Adding support for new tensor formats or quantization schemes
