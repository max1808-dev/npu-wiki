This page documents the hardware architecture constraints in the Ethos-U Vela compiler that determine which neural network operations can be executed on Arm Ethos-U Neural Processing Units (NPUs) and how these operations must be structured to be compatible with the hardware. For information about specific Ethos-U architecture capabilities, see Architecture Support and Ethos-U85 Architecture.

Constraint System Overview

The Ethos-U Vela compiler uses architecture constraints to determine:

  1. Which operations can run directly on the NPU
  2. Which operations need to be decomposed into simpler operations
  3. Which operations must be delegated to the CPU

These constraints are implemented as a hierarchy of classes that provide architecture-specific validation.

Fused Rescaling Support


Fused rescaling allows quantization parameters to be adjusted while executing operations, avoiding the need for separate rescale operations. Both architectures support fused rescaling, but with different constraints:


Input Feature Map (IFM) Rescaling


For Ethos-U55:


    

  • Elementwise operations: Only simple rescaling with 8/16-bit types and no clipping
    • 

  • Limited operation support (Add, Sub, without clipping)
    • 

  • Other ops: Only unit scale without clipping
    • 



For Ethos-U85:


    

  • Broader support for elementwise operations
    • 

  • Div and Mul operations require unit scale
    • 



Output Feature Map (OFM) Rescaling


For Ethos-U55:


    

  • Supported for convolution, depthwise, pooling, and vector product
    • 

  • Limited elementwise support
    • 



For Ethos-U85:


    

  • Supported for convolution, depthwise, pooling, and vector product
    • 

  • Resize operations with scale=1 and shift ≥ 16
    • 

  • Broader elementwise support
    •

Constraint Validation Example


When an operation is processed, the Vela compiler checks if it can be executed on the target hardware:


    

  1. The operation is analyzed to create an ExecutionQuery structure
    2. 

  2. The CanExecute method validates the operation against hardware constraints
    3. 

  3. If the operation can't be executed directly, the compiler checks if it can be decomposed
    4. 

  4. If decomposition is possible, the operation is split into supported operations
    5. 

  5. If decomposition isn't possible, the operation is delegated to the CPU
    6. 



This process ensures efficient utilization of the NPU while maintaining compatibility with operations it doesn't directly support.
