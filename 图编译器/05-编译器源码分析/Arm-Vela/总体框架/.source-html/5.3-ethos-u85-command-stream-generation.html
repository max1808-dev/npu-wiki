Purpose and Scope

This document describes the process of converting high-level neural network operations into low-level register commands specifically for the Ethos-U85 Neural Processing Unit (NPU). It focuses on the final stage of the Vela compilation pipeline where abstract operations are translated into hardware-specific command streams that can be directly executed by the Ethos-U85 NPU. For information about the high-level command stream representation, see High-Level Command Stream. For details on weight compression used during command generation, see Weight Compression.

Overview of Command Stream Generation

The command stream generation process converts abstract neural network operations into concrete register settings that configure the Ethos-U85 hardware to execute these operations. This translation bridges the gap between the computational graph representation and the physical hardware execution.

Command Stream Components

The command stream for Ethos-U85 consists of two main types of commands:

  1. Register setting commands (NPU_SET_*) - Configure various aspects of the NPU such as memory regions, precision, padding, etc.
  2. Operation commands (NPU_OP_*) - Trigger the execution of specific operations like convolution, pooling, etc.

High-Level to Register Command Conversion Process

The conversion from high-level commands to register commands follows a systematic process:

  1. High-level command interpretation: Each HLCStripe or HLCDMA command is processed according to its operation type.
  2. Memory access analysis: Memory regions accessed by each operation are tracked to manage dependencies.
  3. Register command generation: Specific register settings are generated for each operation type.
  4. Command emission: Generated commands are emitted, with optimizations to avoid redundant settings.

Command Generation for Different Operation Types

The Ethos-U85 command stream generator handles various types of neural network operations, each requiring specific register settings.

Convolution Operations

For convolution operations (including standard and depthwise convolutions), the generator:

  1. Sets up input/output feature map configurations
  2. Configures kernel parameters
  3. Sets up weight and bias data
  4. Manages memory dependencies

Pooling Operations

For pooling operations (max pooling, average pooling, etc.), the generator:

  1. Configures the pooling mode (max, average, etc.)
  2. Sets up kernel parameters
  3. Handles special scaling for average pooling

The generator supports these pooling modes:

  • Average pooling (standard or sum-based for kernels > 8x8)
  • Max pooling
  • ArgMax (finding the maximum value's position)
  • Reduction operations (min, max, sum)

Elementwise Operations

For elementwise operations (add, subtract, multiply, etc.), the generator:

  2. Sets up appropriate scaling for maintaining quantization correctness

The supported elementwise operations include:

  • Comparison operations (Equal, Greater, GreaterEqual, NotEqual)
  • Logical operations (And, Or, Xor, Not)

Memory Access Management

The command stream generator carefully manages memory accesses to ensure correct operation execution order and prevent conflicts.

Memory Regions

The Ethos-U85 architecture uses several memory regions:

  1. Feature Map Memory - Stores input and output feature maps
  2. Weight Memory - Stores weights for convolution operations
  3. Staging Memory - Provides fast temporary storage
  4. LUT Memory - Stores lookup tables for activation functions

Memory Access Tracking

The generator tracks memory accesses using the MemoryAccess structure, which records:

  • Access direction (read or write)
  • Memory area being accessed
  • Start and end addresses

This tracking enables:

  1. Detecting conflicts between operations
  2. Calculating wait dependencies
  3. Optimizing memory usage

Operation Dependencies and Block Dependencies

The generator handles dependencies between operations through:

  1. Memory access dependencies - Tracked using memory access analysis
  2. Block dependencies - Calculated for consecutive operations that share data

The block dependency mechanism (BLOCKDEP) optimizes execution by allowing overlapped execution of consecutive operations when safe to do so.

Special Features and Optimizations

Operation Chaining

The Ethos-U85 supports operation chaining, where the output of one operation directly feeds into the next without writing to memory. The generator handles this by:

  1. Setting appropriate storage modes (activation_storage::CHAINED)
  2. Managing register state across operations
  3. Clearing chaining registers when needed

For operations using lookup tables (LUT), such as activation functions, the generator:

  1. Allocates LUT slots in LUT memory
  2. Manages LUT transfers from constant memory
  3. Sets up appropriate LUT configurations

Conclusion

The Ethos-U85 command stream generation system efficiently converts high-level neural network operations into low-level hardware commands. Through careful management of memory accesses, operation dependencies, and hardware-specific optimizations, it enables the effective execution of neural network models on the Ethos-U85 NPU.
