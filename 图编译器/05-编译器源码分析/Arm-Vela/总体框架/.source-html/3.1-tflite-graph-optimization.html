This page documents the TensorFlow Lite (TFLite) graph optimization process in the Ethos-U Vela compiler. These optimizations transform a TFLite neural network graph to run efficiently on Arm Ethos-U Neural Processing Units (NPUs).

Purpose and Scope

The TFLite graph optimizer serves as an early optimization phase in the Vela compilation pipeline. It transforms the original TFLite graph to:

  1. Eliminate inefficient operations
  2. Rewrite operations for better NPU execution
  3. Convert unsupported operations into equivalent supported ones
  4. Apply operator-specific optimizations for better memory usage and performance

This document focuses specifically on TFLite graph optimization. For TOSA graph optimization, see TOSA Graph Optimization. For information about supported operators, see Supported Operators.

Overview of TFLite Graph Optimization

TFLite graph optimization occurs early in the compilation pipeline after the TFLite model is read but before operation scheduling.

Optimization Techniques


The TFLite graph optimizer applies numerous optimizations to the graph. Here are the key techniques:


Removing Passthrough Tensors


Identity operations (like Op.Identity) are eliminated by directly connecting their inputs to their outputs, reducing memory transfers and computational overhead.




Sources: ethosu/vela/tflite_graph_optimiser.py84-88


Rewriting Concat Operations


Concat operations are rewritten to use a series of average pool operations, which are more efficiently executed on the NPU.




The rewritten operation creates separate average pool operations for each input, each writing to a specific slice of the output tensor.


Sources: ethosu/vela/tflite_graph_optimiser.py91-133


Rewriting Split Operations


Split operations are rewritten to use SplitSliceRead operations that read specific slices from the input tensor.

Converting Resize Operations


Resize operations (ResizeBilinear, ResizeNearestNeighbor) are converted to either:


    

  1. Average pool operations with upscaling
    2. 

  2. Depthwise convolutions

Converting ArgMax


ArgMax is converted to a sequence of operations: DepthwiseConv2D → MaxPool → DepthwiseConv2D.




This conversion allows ArgMax to execute efficiently on the NPU hardware.

Rewriting Fully Connected Input


Reshapes the input tensor of fully connected operations to 2D format for NPU compatibility.

Supported Operators and Constraints


The TFLite graph optimizer works with a predefined set of supported operators. Each operator has general and specific constraints that must be satisfied for the operator to be executed on the NPU.


General Constraints


These constraints apply to most operators:































ConstraintDescription
Tensor Data TypesMust be int8, uint8, int16, or int32 (limited ops)
Tensor DimensionsMust be in range [1, 65535]
Tensor ShapeCannot be more than 4D
Batch SizeMust be 1 (except for specific ops)
Fused ActivationMust be one of the supported types

The TFLiteSupportedOperators class contains logic to check if an operator can be executed on the NPU. It validates:


    

  1. General constraints applicable to most operators
    2. 

  2. Operator-specific constraints (e.g., stride size, kernel dimensions)
    3. 



If all constraints are satisfied, the operator can run on the NPU; otherwise, it will be executed on the CPU.

Example: Optimization of Resize Operation


Resize operations are particularly complex and can be optimized in several ways:


    

  1. 1x1 Input: Converted to an Add operation with a zero tensor
    2. 

  2. ResizeBilinear with half_pixel_centers: Converted to depthwise convolutions with specific kernels
    3. 

  3. Standard Resize: Converted to a series of 1x1 average pools with nearest neighbor upscaling
    4. 





For ResizeBilinear with half-pixel centers, four depthwise convolutions are created, each handling a quadrant of the output (TL, TR, BL, BR). The kernels contain interpolation coefficients calculated based on the resize factor.

Summary


The TFLite Graph Optimization module is a critical component of the Vela compiler that transforms TensorFlow Lite operations to run efficiently on Ethos-U NPUs. It applies a series of optimizations to:


    

  1. Eliminate unnecessary operations (remove passthrough tensors)
    2. 

  2. Convert unsupported operations to supported ones (resize, argmax)
    3. 

  3. Rewrite operations for better performance (concat, split)
    4. 

  4. Reshape inputs for NPU compatibility (fully connected)
    5. 



These optimizations are essential for achieving optimal performance and memory usage on Ethos-U NPUs. After optimization, the system checks whether each operator meets the constraints required for NPU execution. Operators that don't meet these constraints will run on the CPU instead.
