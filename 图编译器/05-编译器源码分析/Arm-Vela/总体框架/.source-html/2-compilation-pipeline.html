The Compilation Pipeline is the core process of the Ethos-U Vela compiler that transforms input neural network models (TensorFlow Lite or TOSA) into optimized models that can efficiently execute on Arm Ethos-U Neural Processing Units (NPUs). This document outlines the end-to-end compilation flow, detailing the steps from input model parsing to optimized output generation.

For details about specific optimization techniques applied to neural network graphs, see Graph Optimization. For information about command stream generation, see Command Stream Generation.

High-Level Compilation Flow

The Vela compiler comprises a series of well-defined processing stages that systematically transform and optimize the neural network model.

Compilation Paths

Vela supports two compilation paths:

  1. Traditional Path - Default for Ethos-U55 and Ethos-U65
  2. Regor Path - Default for Ethos-U85, can be enabled for U55/U65 with --debug-force-regor

While both paths share the same general flow, they use different implementation strategies for some components. This document primarily focuses on the traditional path, which is more established.

1. Model Reading

The first step is parsing the input model and converting it to Vela's internal Neural Network Graph (NNG) representation.

Key components:

  • TFLite Reader: Parses TensorFlow Lite models, extracts operators, tensors, and builds the internal graph
  • TOSA Reader: Experimental support for TOSA format models
  • Network Type Detection: Identifies model format based on magic numbers (TFLITE_MAGIC: 0x334C4654, TOSA_MAGIC: 0x41534F54)

The read model becomes the foundation for all subsequent optimization steps.

Sources: ethosu/vela/vela.py71 ethosu/regor/tflite/tflite_reader.cpp120-366

2. Graph Optimization

Once the neural network graph is constructed, the graph optimization phase applies various transformations to improve execution efficiency.

Key optimizations include:

  • Removal of passthrough tensors
  • Rewriting concat and split operations
  • Converting resize operations
  • Reordering weights for efficient memory access
  • Fixing bias tensor dimensions and quantization

During this phase, each operation is evaluated to determine if it can run on the NPU or needs to fall back to CPU.

3. Tensor Purpose Marking and Pass Packing

The next phases mark tensor purposes and pack operations into passes:

Tensor purposes include:

  • Weights
  • Biases
  • Feature maps (activation data)
  • Intermediate data

A pass represents one or more operations that can be executed together as a single hardware operation, typically including an operation and its activation function.

Summary


The Ethos-U Vela Compilation Pipeline transforms neural network models through a series of optimizations tailored for Arm Ethos-U NPUs. The process includes graph optimization, tensor allocation, scheduling, and command stream generation, resulting in models that efficiently utilize the NPU's capabilities.


By understanding the compilation pipeline, developers can better optimize their models for the Ethos-U NPU and utilize the various configuration options to achieve the best performance for their specific deployment scenarios.
