The Ethos-U Vela compiler provides a comprehensive command-line interface (CLI) that allows users to optimize neural network models for Arm Ethos-U Neural Processing Units (NPUs). This page documents the CLI options, basic usage patterns, and how the command-line interface integrates with the overall compilation process. For information about the configuration options that can be used with the CLI, see Configuration Options.

Overview

The Vela compiler CLI is the primary interface for transforming TensorFlow Lite or TOSA neural network models into optimized versions that can run on embedded systems containing an Arm Ethos-U NPU. The CLI handles all aspects of the compilation process, from reading input models to generating performance estimates and debug information.

Installation and Access

The Vela compiler can be installed via pip, which makes the vela command available from the command line:

pip install ethos-u-vela

After installation, the CLI can be invoked with the vela command followed by various options.

Basic Usage

The simplest way to use the Vela compiler is to provide the path to an input network model file:

vela my_model.tflite

This will compile the model using default settings and output the optimized version to the ./output directory with a _vela suffix added to the filename.

Common Usage Patterns

Here are some common usage patterns for the Vela CLI:

  1. Specify output directory:

    vela --output-dir ./results_dir /path/to/my_model.tflite

  2. Target specific accelerator configuration:

    vela --accelerator-config ethos-u65-512 my_model.tflite

  3. Optimize for size instead of performance:

    vela --optimise Size my_model.tflite

  4. Set memory constraints:

    vela --optimise Performance --arena-cache-size 300000 my_model.tflite

  5. Use a specific system configuration:

    vela --config Arm/vela.ini --system-config My_Sys_Config --memory-mode My_Mem_Mode my_model.tflite

Using the CLI with Configuration Files


The Vela CLI can use configuration files to specify complex system and memory configurations. This is done using the --config, --system-config, and --memory-mode options:


vela network.tflite --config Arm/vela.ini --system-config Ethos_U55_High_End_Embedded --memory-mode Shared_Sram



The configuration file is a Python ConfigParser .ini file that contains sections for system configurations and memory modes. A complete explanation of the configuration file format can be found in the Configuration Options page.

Performance Reporting


The CLI includes functionality to display performance estimates for the compiled network. These estimates are printed to the console by default and can also be written to CSV files:


vela network.tflite --verbose-performance



This will provide a detailed breakdown of performance metrics for each operation in the network, while the standard output includes a summary of overall performance.

Troubleshooting


When using the Vela CLI, users may encounter warnings or errors. These should be thoroughly reviewed as they indicate decisions or problems that occurred during compilation.


Common issues that can be addressed through CLI options:


    

  • Memory constraints: Use --optimise Size or set a specific --arena-cache-size
    • 

  • Recursion errors: Increase the --recursion-limit
    • 

  • Performance issues: Use --verbose-performance to identify bottlenecks
    • 

  • Debug information: Enable --enable-debug-db for more detailed debugging
    • 



For detailed understanding of operators that can be placed on the NPU, use:


vela --supported-ops-report



This generates a comprehensive report of supported operators and their constraints.
