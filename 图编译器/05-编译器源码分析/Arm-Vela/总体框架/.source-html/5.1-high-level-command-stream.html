The High-Level Command Stream is an intermediate representation within the Ethos-U Vela compiler that bridges the gap between the scheduler's operation sequencing and the low-level register command stream. It represents neural network operations as abstract commands that can be efficiently translated into hardware-specific instructions for the Ethos-U NPU.

For information about register-level command generation, see Ethos-U85 Command Stream Generation.

Purpose and Role in the Compilation Pipeline

The High-Level Command Stream serves several critical functions:

  1. Partitions operations into manageable "stripes" that can be processed by the NPU
  2. Represents data movement operations between memory regions
  3. Handles padding, strides, and tensor coordinate transformations
  4. Prepares operations for conversion to hardware-specific register commands

Command Structure and Types

The High-Level Command Stream consists of three primary command types, all derived from a common Command base class:

Command Types

  1. NpuStripe: Represents a computational slice to be executed on the NPU. It defines:

    • The input and output feature maps (IFM, IFM2, OFM)
    • Tensor regions involved (represented by Box objects)
    • Weight and scale tensors (if applicable)
    • Padding information and block configuration

  2. DMA: Represents a Direct Memory Access operation for data transfer between memory regions.

    • Source and destination tensors
    • Box defining the region to be transferred

  3. NOP: A no-operation command, typically used when a DMA would be generated but the source and destination addresses are the same.

Sources: ethosu/vela/high_level_command_stream.py206-321

The Box Class

The Box class is a fundamental component that represents a region of a tensor defined by start and end coordinates. It provides methods for:

  • Transforming coordinates based on strides and skirt (padding) values
  • Checking if one box is contained within another
  • Calculating the size and shape of the region

The most complex method is transform_with_strides_and_skirt, which calculates how the output feature map coordinates map to input feature map coordinates, taking into account:

  • Stride values
  • Padding (skirt)
  • Kernel dimensions
  • Upscaling factors
  • Split/concat operations

This transformation is crucial for correctly computing the input regions needed for a given output region.

Command Stream Generation

The high-level command stream is generated from a schedule produced by the operation scheduler. The process is handled by the generate_high_level_command_stream_for_schedule function.

Sources: ethosu/vela/high_level_command_stream_generator.py51-73 ethosu/vela/high_level_command_stream_generator.py76-262

Stripe Generation

Operations are broken down into stripes based on:

  1. Height stripes: Partitioning the output feature map height
  2. Width stripes: Further dividing each height stripe into width segments
  3. Depth (channel) stripes: Dividing the output channels into manageable portions

For each stripe, the generator:

  1. Creates an OFM (output feature map) box defining the stripe's output region
  2. Calculates the corresponding IFM (input feature map) boxes needed for the computation
  3. Determines padding requirements (pad_top, pad_bottom)
  4. Handles weight transfers if needed via DMA operations
  5. Creates an NpuStripe command with all the necessary information

Sources: ethosu/vela/high_level_command_stream_generator.py156-262

Cascade Handling

Cascades are sequences of operations that can be efficiently executed together without storing intermediate results in memory. The command generator handles cascades by:

  1. Identifying which operations are part of cascades
  2. Starting the generation from the last operation in the cascade
  3. Ensuring input data dependencies are satisfied by recursively generating commands for producer operations

This approach allows for more efficient execution by minimizing memory transfers for intermediate results.

Command to NPU Operation Conversion

After generating the high-level command stream, each command is converted to an NPU operation by the convert_command_to_npu_op function. These NPU operations are closer to the hardware and serve as input for the register command generation.

Feature Map Creation

For each NPU operation, feature maps (IFM, IFM2, OFM) are created with information about:

  1. Memory region: Based on the tensor's memory type (Permanent, Scratch, Scratch_fast)
  2. Data type: Mapped from tensor data type to NPU data type
  3. Layout: NHWC or NHCWB16
  4. Tiles: Height, width, and memory addresses
  5. Strides: For navigating the tensor in memory
  6. Shape: Height, width, and depth
  7. Quantization: Scale and zero point

The create_feature_map function handles the creation of these feature maps with all the necessary attributes.

Quantization Handling

The High-Level Command Stream handles quantization parameters for tensors:

  1. For input feature maps (IFM, IFM2), the get_ifm_or_ifm2_quantization function retrieves the quantization parameters
  2. For output feature maps (OFM), the get_ofm_quantization function is used
  3. Special handling ensures zero points are set to 0 for certain operation types
  4. Explicit scaling is applied when needed for operations like Add, Mul, Sub, LeakyRelu, etc.

Summary

The High-Level Command Stream forms a crucial bridge in the Ethos-U Vela compiler pipeline, translating scheduled operations into a form that can be efficiently converted to hardware-specific commands. By breaking operations into stripes, handling memory transfers with DMAs, and managing tensor coordinates through the Box class, it enables the effective execution of neural networks on Ethos-U NPUs.

The generation of the command stream and its conversion to NPU operations involve complex transformations to handle tensor layouts, memory regions, padding, strides, and quantization parameters. These transformations ensure that the neural network computations are correctly and efficiently mapped to the hardware capabilities.
