This page describes how neural network data is represented within the Ethos-U Vela compiler, focusing on tensor representation, memory management, and data serialization. For information about how tensors are allocated in memory, see Memory Management and Tensor Allocation.

Tensor Class Overview

The Tensor class is the fundamental data structure in Vela that represents neural network tensors. All data in the compiler flows through these tensor objects, which maintain the shape, data type, values, and other properties of tensors as they progress through the compilation pipeline.

Sources: ethosu/vela/tensor.py362-937 ethosu/vela/tensor.py212-295

Tensor Properties

Core Properties

The basic properties of a Tensor include:

  • Shape: The dimensions of the tensor (stored as a list of integers)
  • Data Type: The type of data for each element (represented by the DataType class)
  • Name: A unique identifier for the tensor
  • Values: The actual data of the tensor (stored as a NumPy array)

Each tensor also maintains references to the operations that produce it (ops) and the operations that consume it (consumer_list), creating a graph structure.

Sources: ethosu/vela/tensor.py404-452

Memory Management

Tensors in Vela are assigned to different memory areas and types:

  • Memory Area (mem_area): Defines the physical memory where the tensor is stored (SRAM, DRAM, Flash, etc.)
  • Memory Type (mem_type): Defines how the tensor is used in memory (Permanent, Scratch, etc.)
  • Address: The location of the tensor in memory

Memory addresses are tracked using the TensorAddressMap class which maintains a mapping between tensor equivalence IDs and memory addresses.

Sources: ethosu/vela/tensor.py48-106 ethosu/vela/tensor.py341-360

Tensor Classification

Purpose and Sub-purpose

Tensors are classified based on their purpose and sub-purpose:

  • Purpose (purpose): The primary function of the tensor (Weights, FeatureMap, Scratch, etc.)
  • Sub-Purpose (sub_purpose): Additional classification for special handling (Standard, DoubleBuffer, RollingBuffer, etc.)

This classification affects how tensors are processed, optimized, and allocated in memory.

Sources: ethosu/vela/tensor.py109-156 ethosu/vela/mark_tensors.py28-102

Format

The tensor format defines how the data is laid out in memory:

  • NHWC: Standard format with dimensions [Batch, Height, Width, Channel]
  • NHCWB16: Block-based format specific to the Ethos-U NPU
  • WeightsCompressed: Format for compressed weight tensors

The format is set based on the tensor's purpose and architecture constraints using the set_format method.

Sources: ethosu/vela/tensor.py159-166 ethosu/vela/tensor.py544-570

Quantization

Quantization parameters are crucial for efficient execution on the Ethos-U NPU. The QuantizationParameters class stores:

  • Scale: The factor by which quantized values are multiplied to get real values
  • Zero Point: The quantized value that corresponds to the real value 0
  • Min/Max: The bounds of the original values before quantization
  • Number of Bits: The bit-width used for quantization

These parameters enable conversion between quantized integer values and real floating-point values.

Sources: ethosu/vela/tensor.py212-295

Tensor Creation and Manipulation

Vela provides several utility functions for creating and manipulating tensors:

  • create_const_tensor: Creates a constant tensor with given values
  • create_virtual_tensor: Creates a virtual tensor for internal representation
  • clone: Creates a copy of an existing tensor, optionally with a unique ID
  • transpose: Reorders the dimensions of a tensor

These functions help in building and transforming the neural network graph during optimization.

Sources: ethosu/vela/tensor.py297-337 ethosu/vela/tensor.py494-526

Memory Layout and Addressing

Tensors in Vela have three shape representations:

  • shape: The logical shape of the tensor as defined in the model
  • storage_shape: The shape in memory after rounding to storage quantum sizes
  • bandwidth_shape: The shape used for bandwidth calculations

The storage shape can differ from the logical shape due to memory alignment requirements and optimizations.

Sources: ethosu/vela/tensor.py566-584 ethosu/vela/tensor.py177-203

For tensors in specific formats like NHCWB16, addressing requires translating from logical coordinates to physical memory addresses. The address_for_coordinate method handles this conversion.

Sources: ethosu/vela/tensor.py808-851

TFLite Serialization and Deserialization

Reading TFLite Models

The TFLite reader parses TensorFlow Lite models and converts them to Vela's internal representation:

Sources: ethosu/vela/tflite_reader.py47-368

During parsing:

  1. Tensor shapes, types, and quantization parameters are extracted
  2. Tensor values (for constants) are loaded from buffers
  3. Operations are created and linked to their input and output tensors

Writing TFLite Models

The TFLite writer serializes Vela's optimized graph back to TensorFlow Lite format:

Sources: ethosu/vela/tflite_writer.py77-554

During serialization:

  1. Tensors are assigned to buffers
  2. Quantization parameters are serialized
  3. Operators and their attributes are converted to TFLite format
  4. Memory allocation information is added as metadata

NPU Subgraph Serialization

For NPU execution, subgraphs need to be serialized into a format that can be processed by the Ethos-U NPU:

Sources: ethosu/vela/npu_serialisation.py33-118

The serialization process includes:

  1. Creating memory tensors for different purposes (scratch, flash, command stream)
  2. Copying compressed weight values and input feature map values to the appropriate tensors
  3. Generating a command stream that can be executed by the Ethos-U NPU driver

Tensor Purpose Marking

The mark_tensors.py module determines the purpose of each tensor in the graph:

Sources: ethosu/vela/mark_tensors.py27-114

The purpose marking process:

  1. Identifies disconnected outputs and marks them as feature maps
  2. Identifies weight tensors based on their connection to operations
  3. Assigns purposes to tensors (Weights, FeatureMap, Scratch, etc.)
  4. Sets the appropriate format, memory area, and memory type based on the purpose

Conclusion

Data representation in the Ethos-U Vela compiler centers around the Tensor class, which provides a flexible and extensible way to represent neural network data. Tensors are classified by purpose, format, and memory location, and they include quantization parameters for efficient execution on the Ethos-U NPU.

The compiler reads tensors from TFLite models, optimizes them, and serializes them back to TFLite format with the appropriate memory allocation information. NPU subgraphs are serialized into a format that can be executed by the Ethos-U NPU driver.
