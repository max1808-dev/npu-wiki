For information about architecture constraints, see Architecture Constraints.

Overview of the Ethos-U85 NPU

The Ethos-U85 is an advanced NPU designed by Arm for efficient execution of neural network workloads. It's available in several configurations with different computational capacities, measured in Multiply-Accumulate operations per cycle (MACs).

Memory Subsystem

The Ethos-U85 contains a hierarchical memory system optimized for neural network operations:

  1. Input Feature Map (IFM) RAM: Stores input tensors
  2. Accumulator (ACC) RAM: Stores intermediate results
  3. Circular Buffer (CB) RAM: Stores weights and constants
  4. Output Buffer (OB) RAM: Stores output tensors

The size of each memory component varies based on the specific Ethos-U85 configuration as shown in the table above.

Microblock Structure and Processing

The Ethos-U85 processes data in small chunks called "microblocks" which are building blocks for operations. Each configuration supports different microblock shapes to optimize for different operation types.

Output Feature Map (OFM) microblocks are the fundamental processing units in the Ethos-U85. Different configurations support different microblock shapes:

Traversal Strategies

The Ethos-U85 supports different traversal strategies to optimize the processing of different operation types:

Traversal TypeDescription
DepthFirstProcesses all depth channels for each spatial location

DepthwiseSpecialized traversal for depthwise convolutions

The traversal strategy is selected based on the operation type and tensor characteristics to optimize performance.

Block Configuration and Optimization

The Ethos-U85 NPU requires careful configuration of processing blocks to optimize performance. The compiler needs to determine:

  1. The optimal OFM microblock for each operation
  2. The corresponding IFM block size
  3. The accumulator type and source

This process is handled by the FindBlockConfig method which considers:

  • Operation type
  • Input and output shapes
  • Kernel size
  • Weight format (including sparse weights)
  • Memory constraints

Shape Handling and Memory Management

A fundamental aspect of the Ethos-U85 architecture implementation is the handling of multi-dimensional shapes and memory allocation. The Shape class is a core component that represents tensor dimensions and enables operations like:

  • Dimension manipulation (padding, extraction, permutation)
  • Shape arithmetic (add, subtract, multiply)
  • Rounding and alignment to memory boundaries
  • Tensor layout transformations

Sources: ethosu/regor/common/shape.hpp34-771

Accumulator Types

The Ethos-U85 supports two accumulator types:

  1. Acc32: 32-bit accumulator for 8-bit operations
  2. Acc48: 48-bit accumulator for 16-bit operations and certain scaled operations

The accumulator type is selected based on the input bit width and operation type.

Command Stream Generation

The final stage of compilation for the Ethos-U85 involves generating a command stream that instructs the hardware how to execute operations. This is handled by the EthosU85RCSGenerator (Register Command Stream Generator) class.

Command generation considers all aspects of the operation configuration:

  • Microblock configuration
  • Traversal strategy
  • Accumulator type
  • Memory allocation

Summary

The Ethos-U85 architecture provides a flexible and powerful platform for neural network acceleration. By carefully selecting microblock configurations, traversal strategies, and memory layouts, the Vela compiler can efficiently map neural network operations to the hardware capabilities of the Ethos-U85.
