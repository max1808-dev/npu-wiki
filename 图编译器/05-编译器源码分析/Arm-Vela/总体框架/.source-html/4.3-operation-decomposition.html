This document explains how the Ethos-U Vela compiler decomposes complex neural network operations into simpler operations that can be efficiently executed on the NPU hardware. Operation decomposition is a critical optimization step that enables the execution of operations that would otherwise be too large or complex for direct hardware implementation.

For related topics, see Operation Scheduling for the overall scheduling process and Cascade Building for how operations are grouped for efficient execution.

Overview of Operation Decomposition

Operation decomposition is the process of breaking down complex neural network operations that exceed hardware constraints into multiple simpler operations that collectively produce the same result. This is necessary because the Ethos-U NPU has hardware limitations such as:

  • Maximum supported tensor dimensions
  • Restrictions on kernel sizes
  • Memory constraints for intermediate results
  • Limits on input feature map (IFM) and output feature map (OFM) sizes

Decomposition Strategies

The compiler employs several strategies to decompose operations based on their characteristics:

Block Decomposition

Block decomposition splits operations into smaller blocks that can fit within hardware constraints. It's primarily used for convolution operations and elementwise operations with large feature maps.

Sources: ethosu/regor/compiler/scheduler_decompose.cpp534-612 ethosu/regor/compiler/scheduler_decompose.cpp502-530

Axis Slicing

Axis slicing decomposes operations by processing one slice of an axis at a time, which is useful for operations with one or more dimensions that exceed hardware limits.

Sources: ethosu/regor/compiler/scheduler_decompose.cpp283-324

Leading Dimensions Decomposition

For operations with tensors that have more than 3 or 4 dimensions, the compiler decomposes along the leading dimensions to reduce them to 3D or 4D operations that the hardware can handle directly.

Sources: ethosu/regor/compiler/scheduler_decompose.cpp328-343

Operation-Specific Decomposition

Different operation types require different decomposition approaches. The compiler includes specialized decomposition functions for each major operation type:

Convolution Decomposition

Convolution operations (Conv2D, DepthwiseConv2D, TransposeConv2D) are decomposed based on:

  • Batch dimension (one batch at a time)
  • Dilation (converted to operations with stride=dilation and dilation=1)
  • Block size (decomposed into smaller convolutions)
  • Stride (broken down into operations with saved accumulators)

Summary

Operation decomposition in the Ethos-U Vela compiler is a crucial optimization step that enables the execution of complex neural network operations on hardware with specific constraints. The decomposition process:

  1. Checks if an operation can and should be decomposed
  2. Selects the appropriate decomposition strategy based on operation type
  3. Breaks down complex operations into simpler ones that can run on the hardware
  4. Integrates the decomposed operations back into the scheduling process

This approach allows the compiler to efficiently map a wide range of neural network operations to the Ethos-U NPU hardware capabilities.
