Command Stream Generation is the process of converting high-level neural network operations into low-level hardware commands for Arm Ethos-U Neural Processing Units (NPUs). It represents a critical phase in the Vela compiler pipeline, transforming optimized network operations into a format executable by the Ethos-U hardware.

This document explains how the Vela compiler generates the command stream, covering the multi-step process from high-level commands to register-level instructions. For information about specific architectural constraints, see Architecture Support.

Overview of Command Stream Generation

The command stream generation process bridges the gap between optimized neural network operations and hardware-specific instructions. It consists of three main phases:

  1. High-Level Command Stream Generation: Creates abstract commands representing neural network operations and DMA transfers
  2. NPU Operation Conversion: Transforms high-level commands into more concrete NPU operation objects
  3. Register Command Stream Generation: Converts NPU operations into hardware-specific register settings

High-Level Command Stream Generation

The high-level command stream consists of abstract commands representing neural network operations and memory transfers. This step transforms scheduled operations from the Scheduler (see Operation Scheduling) into a sequence of commands.

Command Types

Three main types of high-level commands are supported:

  1. NpuStripe: Represents a slice of a neural network operation to be executed on the NPU
  2. DMA: Represents a memory transfer between different memory areas
  3. NOP: Represents a no-operation command (used for visibility in debugging)

Generation Process

The high-level command stream generation processes scheduled operations as follows:

  1. Process each scheduled operation in execution order
  2. For operations in cascades, generate commands for the entire cascade starting from the last operation
  3. For each operation, compute output feature map (OFM) stripes based on block configuration
  4. For each stripe, calculate input feature map (IFM) regions needed
  5. Generate appropriate commands (NpuStripe, DMA, NOP) based on operation type and memory requirements

NPU Operation Conversion

High-level commands are converted to NPU operations, which are more concrete representations of operations for the Ethos-U NPU. This intermediate format captures all the necessary details for generating register commands.

NPU Operation Types

Four main types of NPU operations are supported:

  1. NpuConv2DOperation: Represents standard convolution operations
  2. NpuConvDepthWiseOperation: Represents depthwise convolution operations
  3. NpuPoolingOperation: Represents pooling operations (Max, Average, ReduceSum)
  4. NpuElementWiseOperation: Represents elementwise operations (Add, Mul, Sub, Min, Max, etc.)
  5. NpuDmaOperation: Represents direct memory access operations

Key Components of NPU Operations

Each NPU operation contains detailed information needed for register command generation:

  • Feature Maps: Input/output feature maps with quantization, layout, and addressing information
  • Kernel: Convolution kernel parameters (size, stride, dilation)
  • Weights/Biases: Address ranges for compressed weights and biases
  • Padding: Padding configuration for the operation
  • Block Configuration: Block sizing for the NPU execution
  • Activation: Post-operation activation function

Conversion Process

The conversion process involves:

  1. Creating appropriate NPU operation objects based on operation type
  2. Populating feature map information (layout, strides, quantization)
  3. Setting kernel parameters and block configuration
  4. Configuring weights, biases, and activations
  5. Handling special cases like padding, striding, and upscaling

Register Command Stream Generation

The register command stream generator converts NPU operations into low-level register settings for the Ethos-U NPU. This is the final step that produces the actual commands executed by the hardware.

Register Command Emitter

The CommandStreamEmitter class is responsible for generating register commands. It maintains state about previously emitted commands to avoid redundancy and supports different command types:

  • cmd0: Simple commands without payloads
  • cmd1: Commands with 32-bit payloads
  • cmd_wait: Special command for synchronization
  • cmd_do_operation: Command to execute an operation

Register Generation Process

The register command stream generation process follows these steps:

  1. Convert each NPU operation into corresponding register settings
  2. Calculate memory access patterns and dependencies between operations
  3. Insert wait operations when necessary
  4. Optimize the command stream by eliminating redundant commands
  5. Generate the final bit stream for the NPU

Weight Compression

Weight compression is a crucial optimization step to reduce memory footprint and bandwidth requirements. The weight compressor encodes weights into a compressed format and generates the necessary scaling factors for correct execution.

Weight Compression Process

The weight compression process includes:

  1. Compressing weights using hardware-specific encoding
  2. Calculating and quantizing scaling factors
  3. Packing bias values with scales
  4. Handling special cases like depthwise convolutions

Weight Compression Optimization

The weight compressor includes several optimizations:

  1. Compression Caching: Reuses previously compressed weights when possible
  2. Double Buffering: Enables continuous execution by preparing the next set of weights while the current set is being processed
  3. Core-specific Encoding: Optimizes weight layout for specific Ethos-U configurations
