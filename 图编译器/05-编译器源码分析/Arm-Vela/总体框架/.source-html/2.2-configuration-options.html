This document describes the configuration options available for the Ethos-U Vela compiler, which allow you to customize the compilation process for different Arm Ethos-U Neural Processing Unit (NPU) devices and system configurations. These options control everything from the target hardware architecture to memory allocation strategies and optimization settings.

For information about using the command-line interface, see Command-Line Interface.

Configuration System Overview

The Vela compiler uses a layered configuration system with three components:

  1. Command-line arguments - Direct options specified when invoking the compiler
  2. Configuration files - INI-format files for system and memory specifications
  3. Default values - Built-in settings when no explicit configuration is provided

Configuration File Structure

Vela configuration files use the Python ConfigParser INI format and contain two main section types:

  1. System Configuration ([System_Config.*]) - Defines hardware characteristics
  2. Memory Mode ([Memory_Mode.*]) - Defines memory usage patterns

Sources: OPTIONS.md602-707

System Configuration Section

System configuration sections define the hardware characteristics and memory connections:

[System_Config.My_Sys_Cfg]
core_clock=500000000             # NPU clock frequency (Hz)
axi0_port=Sram                   # Memory type on AXI0 port
axi1_port=Dram                   # Memory type on AXI1 port
Sram_clock_scale=0.5             # SRAM bandwidth as fraction of core clock
Sram_burst_length=64             # Burst length in bytes
Dram_clock_scale=0.25            # DRAM bandwidth as fraction of core clock

Memory types available are Sram, Dram, OnChipFlash, and OffChipFlash. Each memory type can have parameters for:

  • *_clock_scale - Bandwidth as a fraction of core clock
  • *_ports_used - Number of ports used
  • *_burst_length - Minimum efficient burst length
  • *_read_latency - Read latency in cycles
  • *_write_latency - Write latency in cycles
  • *_max_reads - Maximum outstanding reads
  • *_max_writes - Maximum outstanding writes

Memory Mode Section

Memory mode sections define how memory is allocated and used by the NPU:

[Memory_Mode.My_Mem_Mode]
const_mem_area=Axi1              # AXI port for read-only data
arena_mem_area=Axi0              # AXI port for read-write data
cache_mem_area=Axi0              # AXI port for dedicated SRAM
arena_cache_size=393216          # Size of arena/cache in bytes

Memory modes can inherit from other memory modes using the inherit property:

[Memory_Mode.My_Child_Mode]
inherit=Memory_Mode.My_Mem_Mode  # Inherit from parent
arena_cache_size=262144          # Override specific settings

Memory Modes

Vela supports three primary memory mode configurations that define how memory is used for different purposes:

SRAM Only Mode

In this mode, the NPU only has access to SRAM memory. The compiler uses two regions in the SRAM:

  • const_mem_area for constants (weights, biases)
  • arena_mem_area for the TensorFlow Lite Micro tensor arena

The arena_cache_size parameter defines the size of the arena_mem_area, and the cache_mem_area is not used.

Shared SRAM Mode

In this mode:

  • arena_mem_area points to SRAM
  • const_mem_area points to Flash or DRAM
  • cache_mem_area is not used
  • arena_cache_size defines the size of the arena_mem_area

This mode is useful when SRAM is limited and can be shared with other software components.

Dedicated SRAM Mode

In this mode:

  • cache_mem_area points to SRAM dedicated to the NPU
  • const_mem_area and arena_mem_area point to another memory type (e.g., DRAM)
  • arena_cache_size defines the size of the cache_mem_area

This mode is optimal for performance, as the dedicated SRAM can be fully utilized by the NPU for internal buffers.

Example Configuration Scenarios

Embedded System with Limited SRAM

For an embedded system with limited SRAM, you might use:

vela model.tflite --accelerator-config ethos-u55-64 --config Arm/vela.ini \
    --system-config Ethos_U55_High_End_Embedded --memory-mode Shared_Sram \
    --optimise Size

This configuration:

  • Targets the Ethos-U55 with 64 MACs
  • Uses a high-end embedded system configuration with shared SRAM
  • Optimizes for minimal SRAM usage

High-Performance System

For maximum performance with dedicated SRAM:

vela model.tflite --accelerator-config ethos-u65-256 --config Arm/vela.ini \
    --system-config Ethos_U65_Client_Server --memory-mode Dedicated_Sram \
    --optimise Performance --arena-cache-size 1048576

This configuration:

  • Targets the Ethos-U65 with 256 MACs
  • Uses a client-server system configuration with dedicated SRAM
  • Optimizes for maximum performance with a 1MB arena cache

Advanced Configuration

Hill Climb Tensor Allocator

The default tensor allocator (HillClimb) uses an iterative algorithm to find optimal memory allocations. You can control this with:

  • --tensor-allocator - Set to Greedy, LinearAlloc, or HillClimb
  • --hillclimb-max-iterations - Maximum number of iterations (default: 99999)

System Memory Configuration

For fine-grained control of the memory system, create a custom configuration file with detailed memory specifications:

[System_Config.Custom_System]
core_clock=500000000
axi0_port=Sram
axi1_port=Dram
Sram_clock_scale=0.5
Sram_ports_used=1
Sram_burst_length=64
Sram_read_latency=1
Sram_write_latency=1
Dram_clock_scale=0.2
Dram_ports_used=1
Dram_burst_length=128
Dram_read_latency=10
Dram_write_latency=5
 
[Memory_Mode.Custom_Memory]
const_mem_area=Axi1
arena_mem_area=Axi0
cache_mem_area=Axi0
arena_cache_size=262144

This configuration lets you precisely tune memory parameters for your specific hardware.
