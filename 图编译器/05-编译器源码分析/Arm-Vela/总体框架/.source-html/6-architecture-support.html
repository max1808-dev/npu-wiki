This page provides an overview of the different Arm Ethos-U Neural Processing Unit (NPU) architectures supported by the Vela compiler and their key features. For more specific information about architecture constraints, see Architecture Constraints, and for detailed information about the Ethos-U85 architecture, see Ethos-U85 Architecture.

Supported Architecture Families

The Vela compiler supports three main Ethos-U NPU architecture families, each with different variants based on MAC (multiply-accumulate operations) capabilities:

  1. Ethos-U55: Designed for low-power embedded ML applications
  2. Ethos-U65: For higher performance embedded ML applications
  3. Ethos-U85: Latest generation for high-performance ML with expanded operation support

Memory Spilling

Memory spilling is a feature that allows the Ethos-U NPU to use a dedicated SRAM as a cache for various types of data. This is enabled when:

  1. The cache memory area is SRAM
  2. The cache memory area is different from the arena memory area

The is_spilling_enabled() method in ArchitectureFeatures determines whether this feature is available for a given configuration.

Command Stream Generation

The Vela compiler generates architecture-specific register-level command streams based on the target Ethos-U architecture.

Sources: ethosu/vela/register_command_stream_generator.py17-226

Register Command Types

The CommandStreamEmitter class handles emission of register commands for different architectures. It supports:

  1. Commands without payload (cmd0)
  2. Commands with 32-bit payload (cmd1)
  3. Wait commands for synchronization
  4. Operation execution commands

Each architecture requires different register settings to configure operations properly.

Architecture-Specific Shape Handling

The Vela compiler and its newer components use specialized Shape classes to manage multi-dimensional tensor shapes across different architectures:

  1. The Python-based Block class in Vela's core
  2. The C++ Shape class in newer architecture-specific components

These classes provide functionality for:

  • Creating and manipulating N-dimensional shapes
  • Operations like rounding, padding, and transformation
  • Calculating strides and element counts
  • Optimizing tensor layouts for specific architectures

Summary

The Ethos-U Vela compiler supports multiple Arm Ethos-U NPU architectures with different capabilities and constraints. The architecture support encompasses:

  1. Configuration of architecture-specific parameters
  2. Memory management tailored to each architecture
  3. Operation support based on architecture capabilities
  4. Efficient block size calculation and allocation
  5. Architecture-specific command stream generation
  6. Optimized weight compression

Understanding these architectural differences is crucial for optimizing neural networks for specific Ethos-U hardware targets.
