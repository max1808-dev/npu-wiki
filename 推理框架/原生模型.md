> 本文只讨论 **TensorFlow 原生 SavedModel 格式**，以`Conv2D + BiasAdd + ReLU` 为例，解释 Python> 程序如何被保存为模型，以及模型结构、Tensor
> 信息和权重数据分别存放在哪里。

## 1. 分析对象：TensorFlow 原生程序

下面使用 `tf.Module` 和 `tf.function`，不使用 Keras：

``` python
import tensorflow as tf

class ConvRelu(tf.Module):

    def __init__(self):
        super().__init__()

        # Conv2D 权重：HWIO = [height, width, input_channels, output_channels]
        self.kernel = tf.Variable(
            tf.random.normal([3, 3, 3, 4]),
            name="kernel"
        )

        # 每个输出通道一个 bias
        self.bias = tf.Variable(
            tf.zeros([4]),
            name="bias"
        )

    @tf.function(
        input_signature=[
            tf.TensorSpec(
                [None, 8, 8, 3],
                tf.float32,
                name="input"
            )
        ]
    )
    def __call__(self, x):
        z = tf.nn.conv2d(
            input=x,
            filters=self.kernel,
            strides=[1, 1, 1, 1],
            padding="SAME"
        )

        z = tf.nn.bias_add(z, self.bias)
        y = tf.nn.relu(z)
        return y


model = ConvRelu()

tf.saved_model.save(
    model,
    "conv_relu_saved_model"
)
```

### 1.1 这段程序表达什么？

-   输入 `x`：形状为 `[N, 8, 8, 3]`，数据类型为 `float32`。`N` 是可变的
    Batch 维度。
-   `kernel`：形状为 `[3, 3, 3, 4]`，采用 TensorFlow Conv2D 常见的 HWIO
    布局。
    -   H = 3：卷积核高度。
    -   W = 3：卷积核宽度。
    -   Cin = 3：输入通道数。
    -   Cout = 4：输出通道数。
-   `bias`：形状为 `[4]`，每个输出通道对应一个偏置。
-   `Conv2D`：步长为 1，填充方式为 `SAME`。
-   `BiasAdd`：将 4 个 Bias 分别加到 4 个输出通道。
-   `ReLU`：执行 `max(0, x)`。

在这些条件下，输出形状为 `[N, 8, 8, 4]`。

### 1.2 Python 程序不等于保存后的模型

Python 代码是模型的构建描述。执行 `tf.saved_model.save` 时，TensorFlow
保存的是可恢复的对象、跟踪得到的函数/计算图、变量值及相关元数据，而不是简单地把这段
Python 源代码原样存进模型目录。

`tf.function` 会对函数进行 tracing，产生可执行的
ConcreteFunction。保存时，TensorFlow
将跟踪得到的函数图及其依赖关系序列化。

因此，加载 SavedModel 时，通常不需要原来的 `ConvRelu` Python
类定义，也不需要重新执行原始建模脚本。

## 2. SavedModel 生成的目录结构

执行：

``` python
tf.saved_model.save(model, "conv_relu_saved_model")
```

会生成一个目录。典型结构如下：

``` text
conv_relu_saved_model/
├── saved_model.pb
├── fingerprint.pb                 # 视 TensorFlow 版本而定
├── variables/
│   ├── variables.index
│   └── variables.data-00000-of-00001
└── assets/                         # 可能为空，或不包含文件
```

不同 TensorFlow
版本、保存选项和模型内容可能导致辅助文件或目录有所差异。核心内容是
SavedModel protobuf 文件和变量 checkpoint 文件。

  -------------------------------------------------------------------------------------------------------------------
  文件/目录                                   内容                    主要作用
  ------------------------------------------- ----------------------- -----------------------------------------------
  `saved_model.pb`                            SavedModel protobuf     保存
                                              序列化内容              MetaGraph、计算图、函数、对象关系及相关元数据

  `variables/variables.index`                 Checkpoint 索引         记录变量条目及其数据位置等信息

  `variables/variables.data-00000-of-00001`   Checkpoint 数据分片     保存变量的实际数值

  `fingerprint.pb`                            模型指纹信息            辅助识别模型内容

  `assets/`                                   外部资源                例如模型依赖的词表或其他资源文件
  -------------------------------------------------------------------------------------------------------------------

**重要区别：** `saved_model.pb` 主要描述模型及其结构；`variables.data-*`
保存变量数值；`variables.index` 帮助 TensorFlow 定位和恢复变量。

## 3. 先从计算逻辑理解模型

本例的核心数据流如下：

``` mermaid
flowchart TD
    I["Input<br/>float32 [N, 8, 8, 3]"]
    K["Kernel Variable<br/>float32 [3, 3, 3, 4]"]
    C["Conv2D<br/>strides=[1,1,1,1]<br/>padding=SAME"]
    CO["Conv2D 输出<br/>float32 [N, 8, 8, 4]"]
    B["Bias Variable<br/>float32 [4]"]
    BA["BiasAdd"]
    BO["BiasAdd 输出<br/>float32 [N, 8, 8, 4]"]
    R["ReLU"]
    O["Output<br/>float32 [N, 8, 8, 4]"]

    I --> C
    K --> C
    C --> CO
    CO --> BA
    B --> BA
    BA --> BO
    BO --> R
    R --> O
```

这张图表达的是模型的**逻辑数据流**，不是 `saved_model.pb`
的字节布局，也不保证实际 GraphDef 中的节点名称和节点数量与图中完全一致。

### 3.1 模型需要表达哪些信息？

  ------------------------------------------------------------------------------------------------------
  信息类别                本例中的内容                               用途
  ----------------------- ------------------------------------------ -----------------------------------
  操作类型                Conv2D、BiasAdd、Relu                      说明执行什么计算

  数据依赖                Conv2D → BiasAdd → Relu                    说明节点之间如何连接

  Tensor 规格             Shape、Data Type                           说明数据形状和类型

  算子属性                strides、padding、data_format、dilations   说明算子的计算配置

  变量定义                kernel、bias                               说明模型依赖哪些可训练/可恢复变量

  变量数值                Kernel 和 Bias 的实际元素                  为计算提供参数

  函数输入输出            输入规格、函数返回值                       描述函数调用约定

  对象关系                Module、Variable、函数之间的关系           支持对象恢复和变量跟踪
  ------------------------------------------------------------------------------------------------------

**计算节点与变量数据是两回事：**

-   `Conv2D` 是计算操作，不是卷积权重本身。
-   `kernel` 是变量，保存卷积权重数值。
-   `BiasAdd` 是计算操作，不是 Bias 数值。
-   `bias` 是变量，保存偏置数值。

## 4. saved_model.pb 的内部结构

`saved_model.pb` 是 Protocol
Buffers（Protobuf）序列化文件，不是普通文本文件。它最外层对应
`SavedModel` 消息。

其核心结构可以概括为：

``` text
SavedModel
└── MetaGraphDef
    ├── MetaInfoDef
    ├── GraphDef
    │   ├── node: NodeDef[]
    │   └── library
    │       └── function: FunctionDef[]
    ├── SignatureDef map
    ├── ObjectGraphDef
    └── SaverDef
```

这是概念结构图。各字段是否存在、具体内容以及图如何组织，取决于
TensorFlow 版本、保存方式和模型跟踪结果。

### 4.1 GraphDef：计算图

`GraphDef` 是计算图的主要 protobuf 表示，包含：

-   `node`：图中的节点，每个节点通常用 `NodeDef` 描述。
-   `library.function`：函数库，保存计算图中定义的函数（`FunctionDef`）。

一个 `NodeDef` 的核心信息包括：

  字段      含义
  --------- -------------------------------------------------------
  `name`    节点名称
  `op`      操作类型，例如 `Conv2D`、`BiasAdd`、`Relu`
  `input`   输入边，引用其他节点的输出或控制依赖
  `attr`    节点属性，例如 stride、padding、data format、数据类型

可以把 Conv2D 节点抽象成下面的逻辑示意：

``` text
NodeDef {
    name: "..."
    op: "Conv2D"
    input: "..."
    input: "..."

    attr {
        strides: [1, 1, 1, 1]
        padding: "SAME"
        data_format: "NHWC"
        dilations: [1, 1, 1, 1]
        T: DT_FLOAT
    }
}
```

这只是便于理解的示意，不是保证与某个 TensorFlow 版本实际 dump 完全一致的
protobuf
文本。真实图中还可能有变量读取、函数调用、控制依赖、形状相关节点等。

### 4.2 Conv2D 节点描述什么？

本例 Conv2D 的关键配置如下：

  信息            本例取值        含义
  --------------- --------------- ------------------------------
  Op              `Conv2D`        卷积操作
  输入 1          输入 Tensor     被卷积的数据
  输入 2          Kernel Tensor   卷积滤波器
  `strides`       `[1,1,1,1]`     NHWC 四个维度上的步长
  `padding`       `SAME`          输出空间尺寸按 SAME 规则计算
  `data_format`   `NHWC`          输入/输出数据布局
  `dilations`     `[1,1,1,1]`     空洞卷积参数
  `T`             `DT_FLOAT`      算子输入数据类型

节点通过 `input` 字段连接数据依赖；属性通过 `attr`
描述计算配置。算子节点不需要把整个 Kernel 数值直接写在 `NodeDef`
的属性里。

### 4.3 BiasAdd 节点描述什么？

BiasAdd 接收两个输入：

1.  Conv2D 的输出 Tensor。
2.  Bias Tensor。

它描述的是逐通道偏置加法。对于 NHWC 数据布局，Bias
的长度对应最后一个通道维度。

示意：

``` text
NodeDef {
    name: "..."
    op: "BiasAdd"
    input: "conv_output"
    input: "bias_value"

    attr {
        T: DT_FLOAT
        data_format: "NHWC"
    }
}
```

节点只引用 Bias Tensor，并不负责保存 Bias 的实际数值。

### 4.4 Relu 节点描述什么？

ReLU 接收 BiasAdd 的结果作为输入：

``` text
NodeDef {
    name: "..."
    op: "Relu"
    input: "bias_add_output"

    attr {
        T: DT_FLOAT
    }
}
```

ReLU 的计算规则由 TensorFlow
对应算子实现，节点描述操作类型及输入关系，不需要额外的权重 Tensor。

### 4.5 为什么实际图可能比三个节点复杂？

本例中的 `kernel` 和 `bias` 是
`tf.Variable`。运行函数时，需要从变量资源中读取变量值。实际跟踪图中可能出现：

-   变量资源句柄相关节点；
-   `ReadVariableOp` 等变量读取操作；
-   函数输入、输出及控制依赖相关节点；
-   被放在 `FunctionDef` 中的函数体，而不一定全部直接表现为顶层 GraphDef
    节点。

因此，不能仅凭 Python 代码中写了三个 TensorFlow
运算，就断定序列化后的图一定只有三个节点。节点名称和图的具体组织也可能随版本变化。

## 5. Tensor 的 Shape 和 Data Type

本例的主要 Tensor 如下：

  Tensor            Shape            Data Type   说明
  ----------------- ---------------- ----------- --------------
  input             `[N, 8, 8, 3]`   `float32`   模型输入
  kernel            `[3, 3, 3, 4]`   `float32`   卷积权重
  conv_output       `[N, 8, 8, 4]`   `float32`   Conv2D 输出
  bias              `[4]`            `float32`   偏置
  bias_add_output   `[N, 8, 8, 4]`   `float32`   BiasAdd 输出
  output            `[N, 8, 8, 4]`   `float32`   模型输出

`N` 是动态 Batch 维度。输入 Batch 为 1 时，输出是 `[1,8,8,4]`；输入
Batch 为 4 时，输出是 `[4,8,8,4]`。

Tensor
的类型和形状信息会出现在函数输入输出规格、算子类型约束、图中相关元数据等位置。不要假定所有
Tensor 的 Shape 都以同一种方式、完整地存储在一个独立 Tensor 表中。

## 6. FunctionDef：函数级计算图

`tf.function` 跟踪 Python 函数后，会得到
ConcreteFunction。保存时，相关函数图可以序列化为 SavedModel
中的函数表示。

`FunctionDef` 描述函数的签名、函数体节点及输入输出映射等信息。它与
`GraphDef.node` 中的普通节点共同构成 TensorFlow 的图表示。

概念上，本例函数的逻辑可以写成：

``` text
Function: __call__

Inputs:
    input
    variable resources (kernel, bias)

Operations:
    read kernel variable
    read bias variable
    Conv2D(input, kernel)
    BiasAdd(conv_output, bias)
    Relu(bias_add_output)

Output:
    relu_output
```

这段是逻辑摘要，不是实际 FunctionDef 的逐字段
dump。具体变量捕获方式、函数名和节点排列需要以实际保存文件为准。

## 7. ObjectGraphDef：对象关系

原始 Python 对象大致是：

``` text
ConvRelu (root tf.Module)
├── kernel (tf.Variable)
├── bias (tf.Variable)
└── __call__ (tf.function)
```

SavedModel
不仅要保存函数图，还要跟踪被保存对象及其依赖关系。`ObjectGraphDef`
用于表示 Trackable 对象图，例如模块、变量和函数之间的关系。

它与计算图的职责不同：

-   `GraphDef` / `FunctionDef`：描述计算如何执行。
-   `ObjectGraphDef`：描述被保存对象之间如何关联、如何恢复。

## 8. SignatureDef：对外输入输出接口

`SignatureDef` 用于描述 SavedModel
对外暴露的函数接口，包括输入和输出的名称、TensorInfo、数据类型和形状等。

**需要区分 `input_signature` 和 SavedModel 的 `SignatureDef`：**

``` python
@tf.function(
    input_signature=[
        tf.TensorSpec(
            [None, 8, 8, 3],
            tf.float32,
            name="input"
        )
    ]
)
def __call__(self, x):
    ...
```

这里的 `input_signature`
是对被跟踪函数输入规格的约束，它本身不等于显式导出一个名为
`serving_default` 的 SignatureDef。

如果需要显式导出 Serving 接口，可以这样做：

``` python
concrete_func = model.__call__.get_concrete_function()

tf.saved_model.save(
    model,
    "conv_relu_saved_model",
    signatures=concrete_func
)
```

显式导出后，可以通过 SavedModel 的 Signature
机制查看相应的输入输出接口。具体签名键名和 Tensor
名称应以实际导出结果为准。

## 9. variables：模型变量如何存储？

本例定义两个变量：

``` python
self.kernel = tf.Variable(
    tf.random.normal([3, 3, 3, 4]),
    name="kernel"
)

self.bias = tf.Variable(
    tf.zeros([4]),
    name="bias"
)
```

变量对象及其关系由 SavedModel 的对象跟踪信息描述；变量的实际数值保存在
`variables/` 下的 TensorFlow Checkpoint 中。

### 9.1 Kernel 的大小

Kernel Shape：

``` text
[3, 3, 3, 4]
```

元素个数：

\[ 3 `\times 3`{=tex} `\times 3`{=tex} `\times 4`{=tex} = 108 \]

FP32 每个元素占 4 Bytes：

\[ 108 `\times 4`{=tex} = 432 `\text{Bytes}`{=tex} \]

### 9.2 Bias 的大小

Bias Shape：

``` text
[4]
```

元素个数为 4：

\[ 4 `\times 4`{=tex} = 16 `\text{Bytes}`{=tex} \]

### 9.3 变量数据量汇总

  变量     Shape           元素数 Data Type     数值数据大小
  -------- ------------- -------- ----------- --------------
  Kernel   `[3,3,3,4]`        108 float32          432 Bytes
  Bias     `[4]`                4 float32           16 Bytes
  合计                        112                  448 Bytes

这里的 448 Bytes 只是两个变量的数值数据量，不是整个 Checkpoint
文件大小。索引、元数据、对齐和其他保存对象都会带来额外开销。

另外，`tf.random.normal()`
在模型构建时生成实际随机数。保存时保存的是当时的变量数值，而不是保存一条"以后再执行
random.normal"的 Python 指令。

## 10. variables.index 和 variables.data 的关系

### 10.1 `variables.data-00000-of-00001`

这是 Checkpoint
数据分片，保存变量的实际内容。模型较大时，数据可能分成多个 shard。

可以将其概念性地理解为包含 Kernel、Bias
等变量的数据块，但不能据此推断文件中一定按 Kernel 在前、Bias
在后的顺序排列。

### 10.2 `variables.index`

这是 Checkpoint 索引文件。它记录变量条目及其数据位置相关信息，帮助
TensorFlow 找到相应变量数据。

Checkpoint Bundle 的条目元数据包含的典型信息有：

  字段       含义
  ---------- -----------------
  dtype      Tensor 数据类型
  shape      Tensor 形状
  shard_id   数据所在分片
  offset     分片内数据偏移
  size       数据大小
  crc32c     数据校验信息

概念性索引表：

  变量     dtype     Shape         数据分片        数据大小
  -------- --------- ------------- ------------ -----------
  Kernel   float32   `[3,3,3,4]`   某个 shard     432 Bytes
  Bias     float32   `[4]`         某个 shard      16 Bytes

实际 checkpoint 中的变量键名通常由 Trackable
对象路径等机制确定，可能不是简单的
`kernel`、`bias`。实际偏移、分片和名称应通过工具读取，不能手工假定。

## 12. 实际检查 SavedModel 的方法

以下操作可以直接验证本例生成的模型，不需要猜测文件内部内容。

### 12.1 查看目录

``` bash
find conv_relu_saved_model -maxdepth 3 -type f -print
```

### 12.2 查看 SavedModel 信息

``` bash
saved_model_cli show \
    --dir conv_relu_saved_model \
    --all
```

它可以展示 MetaGraph、签名等信息。若没有显式导出 Serving
Signature，不应假设一定存在 `serving_default`。

### 12.3 列出 Checkpoint 中的变量

``` python
import tensorflow as tf

checkpoint_prefix = (
    "conv_relu_saved_model/variables/variables"
)

for name, shape in tf.train.list_variables(checkpoint_prefix):
    print(name, shape)
```

这可以查看实际 checkpoint 键名和 Shape。

### 12.4 读取变量实际数值

``` python
import tensorflow as tf

checkpoint_prefix = (
    "conv_relu_saved_model/variables/variables"
)

reader = tf.train.load_checkpoint(checkpoint_prefix)

for name, shape in tf.train.list_variables(checkpoint_prefix):
    if name == "_CHECKPOINTABLE_OBJECT_GRAPH":
        continue

    value = reader.get_tensor(name)

    print("Name:", name)
    print("Shape:", value.shape)
    print("Dtype:", value.dtype)
    print("Value:", value)
```

注意：Checkpoint 可能包含对象图等非普通模型权重条目，因此示例中跳过了
`_CHECKPOINTABLE_OBJECT_GRAPH`。

### 12.5 解析 saved_model.pb

``` python
from tensorflow.core.protobuf import saved_model_pb2

saved_model = saved_model_pb2.SavedModel()

with open(
    "conv_relu_saved_model/saved_model.pb",
    "rb"
) as f:
    saved_model.ParseFromString(f.read())

for meta_graph in saved_model.meta_graphs:
    graph_def = meta_graph.graph_def

    print("Top-level Graph Nodes:")
    for node in graph_def.node:
        print(node.name, node.op, list(node.input))

    print("\nFunction Library:")
    for func in graph_def.library.function:
        print("Function:", func.signature.name)

        for node in func.node_def:
            print(node.name, node.op, list(node.input))
```

这段代码分别查看顶层 GraphDef 节点和 FunctionDef
函数库。若某些计算位于函数体中，只查看 `graph_def.node` 就会遗漏它们。

## 13. 核心结论

TensorFlow 原生 SavedModel
不是一个简单的算子列表，也不是一个单纯的权重文件。它是由模型对象、计算图/函数、变量数据和相关元数据组成的可恢复模型表示。

对本例而言：

1.  **`saved_model.pb`**：描述模型对象、函数/计算图、节点连接、算子属性及相关接口元数据。
2.  **`variables.index`**：帮助定位 Checkpoint 中的变量条目。
3.  **`variables.data-*`**：保存 Kernel、Bias 等变量的实际数值。

可以用一句话概括：

> `saved_model.pb` 主要回答"模型如何计算、对象如何关联"；Checkpoint
> 文件主要回答"模型使用的变量数值是什么、如何恢复"。
