# TensorFlow Lite Converter 算子融合能力分析

> 研究范围：只分析 TensorFlow 官方仓库中的 TFLite Converter，不涉及 Vela、NPU 专用图编译器或目标平台模型优化。  
> 代码基线：TensorFlow GitHub `master` 分支，检查日期：2026-11-27。  
> 重要说明：`master` 是滚动分支，本文结论对应检查时的源码状态；正式项目分析建议进一步固定到具体 commit SHA。

---

## 1. 研究结论

TFLite Converter 支持一定程度的算子融合和图重写。

从当前源码看，融合/重写主要包括：

1. 将 ReLU、ReLU6、ReLU1 融入 Conv2D、DepthwiseConv2D、AveragePool2D、MaxPool2D 的 fused activation 属性。
2. 将常量 Add/Sub 折叠进 Conv2D、DepthwiseConv2D、TransposeConv 的 Bias。
3. 将常量 Mul/Div 折叠进 Conv2D、DepthwiseConv2D、TransposeConv 的权重和 Bias。
4. 将 HardSwish 的若干分解计算图识别为一个 `HARD_SWISH`。
5. 将 Add/Sub/Mul/Div 后接 ReLU、ReLU6、ReLU1 的模式改写为带 fused activation 属性的逐元素算子。
6. 将 LeakyReLU、PReLU 等特定分解图识别为对应的 TFLite 算子。
7. 将某些复合 TensorFlow 函数（例如满足规则的 LSTM/RNN composite）转换为 TFLite 内置复合算子；这条路径由 composite preparation/fusion 机制处理，不等同于 `optimize_patterns.td` 中的普通局部 Pattern。

另外还有一些其他的图优化，例如去除冗余 Quantize/Dequantize、折叠 Tile/Broadcast、重排 Transpose/Reshape、BatchMatMul 转 FullyConnected。这些会改变图或减少节点，但不都属于严格意义上的多算子融合。

### 2.2 优化 Pass 在 pipeline 中的位置

当前 `tf_tfl_passes.cc` 的 `AddOptimizationPasses()` 大致组织了：

1. `PushTransposeThroughEwisePass`
2. `OptimizeBroadcastLikePass`
3. `OptimizePass`
4. 在允许时执行 `OptimizeBatchMatmulPass`

TF → TFLite 转换完成后，源码连续调用两轮 `AddOptimizationPasses()`。源码注释说明，后续 Pass 中的融合和重排可能使前面 Pass 中的优化条件成立，因此重复运行优化。

量化流程中也会执行 `OptimizeOpOrderPass` 和 `OptimizePass`，以寻找量化后新增的融合机会。严格 QDQ 路径也会在量化后再次调用优化流程。

因此，Converter 的图优化会执行多次。

## 3. 融合类型一：激活函数融合进卷积和池化算子

### 3.1 支持的前置算子

当前 `optimize_patterns.td` 定义了两个 Pattern 模板：

- `FuseActFnIntoConvOpPat`
- `FuseActFnIntoPoolOpPat`

前者覆盖：
- `TFL_Conv2DOp`
- `TFL_DepthwiseConv2DOp`

后者覆盖：
- `TFL_AveragePool2DOp`
- `TFL_MaxPool2DOp`

### 3.2 支持的激活函数

源码通过 `actFnPair` 明确列出：

| 激活算子 | fused activation 属性 |
|---|---|
| `TFL_ReluOp` | `TFL_AF_Relu` |
| `TFL_Relu6Op` | `TFL_AF_Relu6` |
| `TFL_Relu1Op` | `TFL_AF_Relu1` |

因此，当前源码明确支持以下组合：

| 原始图 | 优化后 |
|---|---|
| Conv2D → ReLU | Conv2D(fused_activation=RELU) |
| Conv2D → ReLU6 | Conv2D(fused_activation=RELU6) |
| Conv2D → ReLU1 | Conv2D(fused_activation=RELU1) |
| DepthwiseConv2D → ReLU | DepthwiseConv2D(fused_activation=RELU) |
| DepthwiseConv2D → ReLU6 | DepthwiseConv2D(fused_activation=RELU6) |
| DepthwiseConv2D → ReLU1 | DepthwiseConv2D(fused_activation=RELU1) |
| AveragePool2D → ReLU | AveragePool2D(fused_activation=RELU) |
| AveragePool2D → ReLU6 | AveragePool2D(fused_activation=RELU6) |
| AveragePool2D → ReLU1 | AveragePool2D(fused_activation=RELU1) |
| MaxPool2D → ReLU | MaxPool2D(fused_activation=RELU) |
| MaxPool2D → ReLU6 | MaxPool2D(fused_activation=RELU6) |
| MaxPool2D → ReLU1 | MaxPool2D(fused_activation=RELU1) |

### 3.3 Pattern 的关键限制

源码对卷积输出和池化输出均要求：

```tablegen
[(HasOneUse $conv_out)]
```

或：

```tablegen
[(HasOneUse $pool_out)]
```

即前置算子的输出只有一个使用者。

原因：如果 Conv2D 的输出同时被 ReLU 和另一个算子使用，就不能把 ReLU 改成 Conv2D 内部属性，否则另一个使用者看到的数据也会被改变，计算语义不再等价。

### 3.4 为什么没有把 Sigmoid、Tanh、HardSwish 放进这组规则？

源码注释明确写明：

> Currently we're not fusing tanh, sigmoid, hard_swish and other activations those cannot be simply translated into clamping.

也就是说，这组“把激活函数变成前置算子 fused activation 属性”的 Pattern 当前只覆盖 ReLU、ReLU6、ReLU1。

这不意味着 HardSwish 完全不支持融合。HardSwish 有独立的图模式识别规则，见第 6 节。

源码位置：
- [`optimize_patterns.td`：FuseActFnIntoConvOpPat / FuseActFnIntoPoolOpPat](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 4. 融合类型二：将 Add/Sub 常量折叠进卷积 Bias

### 4.1 适用算子

源码定义模板：

```tablegen
multiclass FuseBinaryOpToPrecedingAffine<Op binaryOp>
```

并实例化：

```tablegen
foreach binaryOp = [TFL_AddOp, TFL_SubOp]<Op> in
  defm : FuseBinaryOpToPrecedingAffine<binaryOp>;
```

支持的前置算子：
- Conv2D
- DepthwiseConv2D
- TransposeConv

支持的后置二元算子：
- Add
- Sub

### 4.2 计算原理

原始图：

```text
Conv2D(input, weight, bias)
             |
             v
       Add/Sub(constant)
             |
             v
           output
```

如果卷积的 Bias 和 Add/Sub 的另一个输入都是常量，那么可以在编译期计算新的 Bias：

```text
new_bias = old_bias + constant
```

或者：

```text
new_bias = old_bias - constant
```

优化后：

```text
Conv2D(input, weight, new_bias)
             |
             v
           output
```

Add/Sub 节点不再需要单独执行。

### 4.3 支持组合

| 原始图 | 优化方式 |
|---|---|
| Conv2D → Add(Constant) | 常量加到 Conv2D Bias |
| Conv2D → Sub(Constant) | 常量从 Conv2D Bias 中扣除 |
| DepthwiseConv2D → Add(Constant) | 常量加到 DepthwiseConv2D Bias |
| DepthwiseConv2D → Sub(Constant) | 常量从 DepthwiseConv2D Bias 中扣除 |
| TransposeConv → Add(Constant) | 常量折叠进 TransposeConv Bias |
| TransposeConv → Sub(Constant) | 常量折叠进 TransposeConv Bias |

TransposeConv 没有 Bias 的情况也有专门 Pattern：源码会构造相应的 Bias 值，而不是简单地删除 Add/Sub。

### 4.4 重要限制

源码注释说明该 Pattern 当前限制为浮点常量值。除此之外还要求：
- 原始 Bias 是常量（有 Bias 的路径）。
- 常量形状能与卷积通道/Bias 维度匹配。
- `CanFuseConvOrDepthwiseConv` 检查卷积权重和常量的形状/融合条件。
- 前置算子输出只有一个使用者（`HasOneUse`）。

因此不能把任意 Conv2D 后面的 Add/Sub 都认为可以融合。特别是 Add 的另一输入为运行时 Tensor 时，这条常量折叠 Pattern 不适用。

源码位置：
- [`optimize_patterns.td`：FuseBinaryOpToPrecedingAffine](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 5. 融合类型三：将 Mul/Div 常量折叠进卷积权重和 Bias

### 5.1 适用算子

源码模板：

```tablegen
multiclass FuseMulOrDivWithConv2dOrDepthwiseConv2d<Op BinaryOp>
```

实例化的二元算子：

- `TFL_DivOp`
- `TFL_MulOp`

适用前置算子：
- Conv2D
- DepthwiseConv2D
- TransposeConv

### 5.2 计算原理

原始计算：

```text
conv = Conv2D(input, weight, bias)
output = conv * constant
```

利用卷积的线性性质：

```text
new_weight = weight * constant
new_bias   = bias   * constant
```

就可以把乘法折叠到卷积参数中。

除法也有对应 Pattern，按源码的具体操作数方向和常量条件执行等价变换，不能不区分方向地简单写成任意 `Conv / constant` 都能折叠。

### 5.3 支持组合

| 原始图 | 编译期处理 |
|---|---|
| Conv2D → Mul(Constant) | 修改 Conv2D Filter 和 Bias |
| Conv2D → Div(Constant) | 修改 Conv2D Filter 和 Bias |
| DepthwiseConv2D → Mul(Constant) | 修改 Depthwise Filter 和 Bias |
| DepthwiseConv2D → Div(Constant) | 修改 Depthwise Filter 和 Bias |
| TransposeConv → Mul(Constant) | 修改 TransposeConv Weights 和 Bias |
| TransposeConv → Div(Constant) | 修改 TransposeConv Weights 和 Bias |

### 5.4 重要限制

源码注释明确说明该 Pattern 当前限制为浮点常量。实现还检查：
- Filter/Weights 是否为常量。
- Bias 是否为常量，或是否走无 Bias 的专门路径。
- 常量能否按卷积权重布局扩展/广播。
- 前置算子输出是否只有一个使用者。
- `CanFuseConvOrDepthwiseConv` 等形状约束是否满足。

因此，运行时动态 Mul/Div 不能使用这条参数折叠路径。

源码位置：
- [`optimize_patterns.td`：FuseMulOrDivWithConv2dOrDepthwiseConv2d](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 6. 融合类型四：HardSwish 模式识别

HardSwish 的数学定义：

```text
HardSwish(x) = x * ReLU6(x + 3) / 6
```

TensorFlow/模型导出过程中，HardSwish 可能以多个基础算子表示。

例如：

```text
                 x
                 |
          +------+------+
          |             |
          |           Add(3)
          |             |
          |           ReLU6
          |             |
          |           Mul(1/6)
          |             |
          +---- Mul ----+
                 |
               output
```

当前 `optimize_patterns.td` 定义了多个 Pattern：

- `MatchHardSwishPattern1`
- `MatchHardSwishPattern2`
- `MatchHardSwishPattern3`
- `MatchHardSwishPattern4`
- `MatchHardSwishQuantized`
- `MatchHardSwishPattern5`
- `MatchHardSwishPattern6`

这些 Pattern 覆盖了乘法顺序不同、乘以 `1/6` 或除以 `6` 等表达形式，也有处理特定 FakeQuant/QDQ 插入形式的规则。

优化结果：

```text
TFL_HardSwishOp(x)
```

即多个 Add、ReLU6、Mul/Div 节点被识别为一个 TFLite `HARD_SWISH` 算子。

注意：这与把 HardSwish 融入 Conv2D 的 fused activation 属性不是一回事。源码前面明确说明 HardSwish 当前不能简单映射为 Conv2D 的 clamping fused activation，但它可以通过独立 Pattern 被识别为 `HARD_SWISH`。

源码位置：
- [`optimize_patterns.td`：Matching HardSwish](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 7. 融合类型五：逐元素二元算子 + Activation

源码定义：

```tablegen
multiclass FusedBinaryActivationFuncOpPat<Op BinaryOp>
```

并对以下算子实例化：

- Add
- Sub
- Div
- Mul

可融合的激活：
- ReLU
- ReLU6
- ReLU1

因此有：

| 原始图 | 优化后 |
|---|---|
| Add → ReLU | Add(fused_activation=RELU) |
| Add → ReLU6 | Add(fused_activation=RELU6) |
| Add → ReLU1 | Add(fused_activation=RELU1) |
| Sub → ReLU / ReLU6 / ReLU1 | Sub(fused_activation=...) |
| Mul → ReLU / ReLU6 / ReLU1 | Mul(fused_activation=...) |
| Div → ReLU / ReLU6 / ReLU1 | Div(fused_activation=...) |

Pattern 要求前一个二元算子的结果只有一个使用者（`HasOneUse`）。

这类优化减少的是独立 Activation Operator，而不是把 Add/Mul 等算子替换成一个新的专用算子。

源码位置：
- [`optimize_patterns.td`：FusedBinaryActivationFuncOpPat](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 8. 融合类型六：LeakyReLU 模式识别

LeakyReLU 的一种表达：

```text
LeakyReLU(x) = max(x, alpha * x)
```

源码 Pattern 匹配：

```text
Maximum(
    Mul(x, alpha),
    x
)
```

并将其改写为：

```text
TFL_LeakyReluOp(x, alpha)
```

约束：
- `alpha` 必须是浮点常量。
- `alpha < 1`。
- 中间 Mul 输出只有一个使用者。

源码位置：
- [`optimize_patterns.td`：MatchLeakyRelu](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 9. 融合类型七：PReLU 模式识别

源码注释给出的 Keras PReLU 分解：

```text
f(x) = Relu(x) + (-alpha * Relu(-x))
```

原始图：

```text
                 x
                / \
             ReLU  Neg
              |     |
              |    ReLU
              |     |
              |   Mul(-alpha)
              |     |
               \   /
                 Add
                  |
                output
```

优化后：

```text
TFL_PReluOp(x, alpha)
```

源码要求：
- alpha 的 Rank 与输入 Rank 满足指定关系。
- ReLU 分支输出只有一个使用者。
- Mul 分支输出只有一个使用者。
- Neg 的中间结果只有一个使用者。

源码位置：
- [`optimize_patterns.td`：MatchPRelu](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)

## 10. 其他优化

Converter 中还有很多图优化。它们可能减少节点、移动节点或改变算子类型，但不一定是严格意义上的融合。

| 优化 | 源码中的处理 | 是否属于严格多算子融合 |
|---|---|---|
| Quantize(Dequantize(x)) 消除 | 输入输出类型相同则直接替换为原输入 | 否，冗余节点消除 |
| Maximum(x, 0) → ReLU | 识别等价表达 | 算子规范化 |
| Minimum(ReLU(x), 6) → ReLU6 | 识别等价表达 | 算子规范化 |
| Maximum/Minimum 组合 → ReLU1 | 识别等价表达 | 算子规范化 |
| Maximum(x*alpha, x) → LeakyReLU | 多节点模式识别 | 是，复合模式转换 |
| Transpose → Reshape | Trivial Transpose 转换 | 否，算子替换 |
| 两个 Transpose 合并 | 合并 permutation | 否，节点简化 |
| ExpandDims → Reshape | 静态形状下替换 | 否，算子替换 |
| Tile → Add/Mul/Sub/Div | 利用二元算子的广播能力消除 Tile | 否，广播冗余消除 |
| BroadcastTo → 后续支持广播的算子 | `OptimizeBroadcastLikePass` | 通常属于广播折叠，不是计算融合 |
| BatchMatMul → FullyConnected | 独立 `OptimizeBatchMatmulPass` | 否，算子转换 |

特别说明：

- `OptimizeBatchMatmulPass` 在 `tf_tfl_passes.cc` 中单独注册，不能把它算作 `optimize_patterns.td` 中的 Fusion Pattern。
- `PushTransposeThroughEwisePass` 是算子顺序重排。
- `OptimizeBroadcastLikePass` 是广播相关图优化。
- Canonicalizer、CSE、常量折叠、DCE 也可能减少节点，但不等于融合成新的算子。

源码：
- [optimize_patterns.td](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/transforms/optimize_patterns.td)
- [tf_tfl_passes.cc](https://github.com/tensorflow/tensorflow/blob/master/tensorflow/compiler/mlir/lite/tf_tfl_passes.cc)

## 11. Composite Function 融合：LSTM/RNN 等

除了局部的 TFLite Operator Pattern，Converter 还有 Composite Function 的专门处理路径。

在当前 `tf_tfl_passes.cc` 中，可以看到：

```cpp
if (pass_config.emit_builtin_tflite_ops &&
    converter_flags.tf_quantization_mode().empty()) {
  pass_manager->addPass(
      mlir::TFL::CreatePrepareCompositeFunctionsPass());
}
```

源码注释说明，这一步用于融合那些可以降低为 TFLite Builtin Ops 的 composite ops，并且要在 `LowerStaticTensorList` 之前执行。

这条路径和普通 `optimize_patterns.td` 有区别：

| 维度 | 普通 Optimize Pattern | Composite Function |
|---|---|---|
| 输入 | 已经是 TFLite Dialect 的局部算子图 | 带有标记/语义的复合函数 |
| 匹配范围 | 局部相邻或近邻算子 | 函数/复合计算结构 |
| 目的 | 局部融合、规范化、常量折叠 | 将高层复合计算转换为 TFLite 内置复合算子 |
| 例子 | Conv + ReLU、HardSwish | LSTM/RNN 类复合结构 |
| 控制入口 | OptimizePass | PrepareCompositeFunctionsPass 等专门机制 |

需要注意：不能仅凭存在 `PrepareCompositeFunctionsPass` 就断言任意 LSTM/RNN 都能转换。具体支持范围由 composite 定义、匹配函数、转换选项和模型结构决定。

## 12. 当前源码融合能力总表

下表汇总代码中能确认的主要组合。

| 类别                | 原始模式                                | 转换结果                               | 主要限制/条件                   | 源码证据                                      |     |
| ----------------- | ----------------------------------- | ---------------------------------- | ------------------------- | ----------------------------------------- | --- |
| Activation 属性融合   | Conv2D + ReLU/ReLU6/ReLU1           | Conv2D + fused activation          | Conv 输出单一使用者              | `FuseActFnIntoConvOpPat`                  |     |
| Activation 属性融合   | DepthwiseConv2D + ReLU/ReLU6/ReLU1  | DepthwiseConv2D + fused activation | 输出单一使用者                   | `FuseActFnIntoConvOpPat`                  |     |
| Activation 属性融合   | AveragePool2D + ReLU/ReLU6/ReLU1    | AveragePool2D + fused activation   | Pool 输出单一使用者              | `FuseActFnIntoPoolOpPat`                  |     |
| Activation 属性融合   | MaxPool2D + ReLU/ReLU6/ReLU1        | MaxPool2D + fused activation       | Pool 输出单一使用者              | `FuseActFnIntoPoolOpPat`                  |     |
| Bias 常量折叠         | Conv2D + Add/Sub(Constant)          | 修改 Conv Bias                       | 浮点常量、形状约束、单一使用者           | `FuseBinaryOpToPrecedingAffine`           |     |
| Bias 常量折叠         | DepthwiseConv2D + Add/Sub(Constant) | 修改 Depthwise Bias                  | 浮点常量、形状约束、单一使用者           | `FuseBinaryOpToPrecedingAffine`           |     |
| Bias 常量折叠         | TransposeConv + Add/Sub(Constant)   | 修改/创建 Bias                         | 浮点常量、形状约束、单一使用者           | `FuseBinaryOpToPrecedingAffine`           |     |
| 参数常量折叠            | Conv2D + Mul/Div(Constant)          | 修改 Filter 和 Bias                   | Filter/Bias/常量为可处理常量，形状受限 | `FuseMulOrDivWithConv2dOrDepthwiseConv2d` |     |
| 参数常量折叠            | DepthwiseConv2D + Mul/Div(Constant) | 修改 Filter 和 Bias                   | 常量及形状约束                   | 同上                                        |     |
| 参数常量折叠            | TransposeConv + Mul/Div(Constant)   | 修改 Weights 和 Bias                  | 常量及形状约束                   | 同上                                        |     |
| Binary Activation | Add/Sub/Mul/Div + ReLU/ReLU6/ReLU1  | BinaryOp + fused activation        | Binary 输出单一使用者            | `FusedBinaryActivationFuncOpPat`          |     |
| 复合模式识别            | HardSwish 分解图                       | HARD_SWISH                         | 常量值和图形态需匹配                | `MatchHardSwishPattern*`                  |     |
| 复合模式识别            | LeakyReLU 分解图                       | LEAKY_RELU                         | alpha 常量且小于 1，中间值单一使用者    | `MatchLeakyRelu`                          |     |
| 复合模式识别            | PReLU 分解图                           | PRELU                              | Rank 和中间值使用者约束            | `MatchPRelu`                              |     |
| Composite 转换      | 符合规则的 LSTM/RNN composite            | TFLite 内置复合算子                      | composite 规则、选项及图结构决定     | `PrepareCompositeFunctionsPass` 等         |     |

TFLite Converter 的融合能力应当以“源代码 Pattern + pipeline 是否启用 + 运行时模型是否满足约束 + 转换结果验证”四项共同确认。
